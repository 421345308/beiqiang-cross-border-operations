## 2. 独立站的工作原理

独立站由五层组成：

1. **源代码和素材**：保存在 `03_独立站/03_网站源码/`，包括页面文字、产品图、工厂图和询盘交互。
2. **构建**：把源代码整理成浏览器可以加载的正式网页文件。
3. **保存版本**：每次正式修改形成一个可追溯版本；有问题时可以对照旧版本排查。
4. **部署**：推送到 GitHub `main` 后，EdgeOne 自动拉取代码、构建静态文件并发布。
5. **域名与边缘层**：`www.beiqiang.online` 绑定到 EdgeOne，是唯一买家入口；旧 `chatgpt.site` 只作历史记录。

买家的实际路径是：

`Google / TikTok / LinkedIn / 邮件 / Alibaba → 独立站落地页 → 查看鞋款与工厂证据 → 选择款号 → WhatsApp / 邮箱 / Alibaba 发起询盘 → 样品与报价沟通`

## 3. 日常怎么操作

### 固定开发与发布流程（以后每次改站都照此执行）

1. **先定义销售目的**：写清本次改动要改善发现产品、建立信任、资格筛选、联系业务员、样品推进或复购中的哪一环，以及准备观察哪个指标。
2. **读取真实资料**：先读总档案、本 SOP、对应产品数据包和历史发布记录；材料、尺码、颜色、MOQ、价格、交期、包装、认证等没有证据时不写死。
3. **创建变更分支**：在本地仓库 `03_独立站/03_网站源码/` 使用 `codex/主题` 分支开发；正式生产分支保持为 GitHub `main`。
4. **开发与本地验证**：先用 `node --version` 确认 Node.js `>=22.13.0`，再修改 `app/` 和 `public/`；至少运行 `npm test` 与 `npm run edgeone:build`，并检查导出目录中首页和关键产品页存在。本机默认 Node 仍为 20.14.0 时必须切换到 Node 22，不能把 `node:fs/promises.glob` 缺失误判为代码故障。
5. **检查差异**：检查文案、图片、链接、联系方式、移动端、SEO、未确认承诺和 `git diff`，不得把密钥、原始客户资料或无关文件提交到仓库。
6. **提交和发布**：提交到 GitHub；合并或推送到 `main` 后由 EdgeOne 自动部署。当前小团队可直接更新 `main`，改动规模扩大后改为 Pull Request 审核。
   - 2026-08-23 用户已明确持续授权：独立站改动通过自动测试、EdgeOne 导出、ESLint 和差异检查后，Codex 可直接提交并推送 GitHub `main`，无需每次再次询问。该授权不取消正式域名验收、敏感信息检查和故障回滚门禁。
7. **双地址验收**：先检查 EdgeOne 本次临时部署地址，再检查 `https://www.beiqiang.online/`；至少验证首页、改动页、图片、WhatsApp、邮箱、Alibaba 链接和手机端首屏。
8. **记录结果**：在总档案或本 SOP 记录提交号、部署结果、页面变化、指标假设和待观察数据；只有真实浏览器验收通过才标记上线。
9. **回滚**：优先在 Git 中撤销问题提交并重新发布，或在 EdgeOne 选择前一个成功部署；不得用 `git reset --hard` 覆盖未确认的本地工作。

### 已知失败原因与防复发规则

- EdgeOne 曾把仓库根目录识别为 Next.js 并加载 `@edgeone/opennextjs-pages`，随后寻找静态站不需要的 `.next/required-server-files.json`，导致“网站已经导出但部署仍失败”。
- 解决办法是把 Root directory 指向 `edgeone-deploy`，让平台按纯静态项目执行适配脚本；不要随意删掉该目录或把 Root directory 改回仓库根目录。
- `nodejs_compat` 重复声明曾导致旧 Sites 发布失败；当前 EdgeOne 流程不依赖该旧配置。
- `npm audit` 当前报告依赖树存在 18 个问题（1 low、4 moderate、13 high）。这是独立的依赖治理任务；静态构建可用不等于可以忽略，但也不得直接运行 `npm audit fix --force` 破坏项目。

## 4. 当前网站能做什么、不能做什么

当前可以：

- 向买家说明贝强的产品方向和 B2B 合作方式。
- 展示 6 个代表款、产品与工厂照片，并提供 BQ001、BQ002、BQ009/L1026 三个可独立收录的产品页。
- 让买家选择款式并生成采购简报。
- 跳转 WhatsApp、业务邮箱和 Alibaba.com 店铺继续沟通。
- 被搜索引擎和外部研究工具读取。
- 保存合格询盘和来源事件，返回唯一参考号，并在 SMTP 配置有效时通知业务邮箱。
- 通过受保护的内部询盘台账查看记录、排除内部测试并导出 CSV。

当前还不能：

- 自动分配业务员、记录回复时间或推进样品/报价/订单阶段。
- 在站内直接修改询盘状态；当前 CSV 仍需进入销售跟进表继续管理。
- 为每个鞋款提供完整独立页；目前仅完成三个重点款。
- 自动发送产品目录、报价单或样品申请确认。
- 代替 Alibaba.com 的交易保障、订单和付款能力。

因此，现阶段独立站是“获客与筛选入口”，Alibaba.com 是“平台信任与交易承接”，WhatsApp/邮箱是“沟通与推进工具”。三者应互相导流，而不是互相替代。

## 7. 风险边界

- 不公开未确认的最终 FOB 价格、MOQ、交期、库存和产能。
- 不写医疗、矫形、治疗、防水、认证或品牌合作等无证据声明。
- 不使用与实物不一致的 AI 鞋款图。
- 网站发布后必须同时验证“部署状态”和“公开访问权限”。
- 产品、联系方式或访问权限发生重大修改时，在运营总档案留下日期和结果。

## 8. 功能立项判断标准

任何新功能至少要改善以下一项，否则不进入近期开发：

1. 让目标买家更容易从搜索、内容或外联发现对应鞋款。
2. 让买家更快判断贝强是否适合其市场和采购方式。
3. 用真实产品、工厂、样品、质检或包装证据降低采购风险。
4. 收集足以报价和判断买家质量的信息。
5. 让业务员更快收到、分配、回复和跟进询盘。
6. 提高询盘到样品、样品到报价、报价到订单的推进率。

## 15. 2026-08-23 第九阶段：商业漏斗仪表盘

### 如何查看

1. 使用 `INQUIRY_ADMIN_TOKEN` 加载询盘后台后，仪表盘自动读取聚合数据。
2. 可切换 7、30、90 天；短周期用于检查近期改版和投放，长周期用于观察样品、报价和订单推进。
3. `Source signals` 对比 UTM 来源的可选事件和真实询盘；`Product signals` 对比款号浏览、加入清单和询盘。
4. 仪表盘接口只返回汇总，不返回买家姓名、邮箱、消息正文或上传文件。

### 经营判断顺序

1. 浏览少：先检查获客渠道、搜索覆盖和落地页入口。
2. 浏览多但加入清单少：检查首图、款式匹配、已确认规格和 CTA。
3. 加清单多但询盘少：检查询盘字段负担、信任证据和联系替代方式。
4. 询盘多但 Qualified 少：检查渠道定向、买家公司和采购量质量。
5. Qualified 多但样品少：检查响应速度、样品条件、产品证据和未确认参数。
6. 报价多但接受少：复盘价格、贸易条款、MOQ、交期、包装和买家异议。
7. 接受报价但未成订单：核对 Trade Assurance/合同、付款条件和下一步到期日，不能把接受报价统计成订单。

### 数据边界

- 可选事件仅来自明确接受分析的访客，是次数而非独立人数，不能计算成完整站点流量。
- 询盘、报价与订单取自 Blob 业务记录；内部测试自动排除。
- `Qualified now` 等阶段是所选周期内收到询盘的当前状态，不是阶段在该周期发生的次数；后续如需精确阶段耗时，应增加不可覆盖的阶段变更日志。

## 16. 2026-08-23 第十阶段：阶段历史与失单复盘

### 阶段历史

## 21. 2026-08-23 第十二阶段：付款节点

### 业务员记录方法

## 24. 2026-08-23 第十六阶段：重复买家关系记忆

可分享比较链接解决了采购团队在不同设备上还原2至4款候选产品的问题，但成熟B2B采购通常还需要一份可归档、可开会评审的静态材料。网站现可把当前中英文产品比较表单独打印或保存为PDF，让采购人先完成内部选款，再回到同一比较链接发起多款询价。

### 买家与业务员怎么用

1. 在英文`/products/`或中文`/zh/products/`选择2至4款产品，也可打开业务员发送的比较链接。
2. 点击`Print / save comparison PDF`或`打印 / 保存比较PDF`。
3. 在浏览器打印窗口选择“保存为PDF”；打印版只保留比较标题、已选择款号、产品图片与公开事实、报价前待确认项、内部决定栏和联系方式。
4. 采购团队可在PDF或打印件中标记`Preferred / 首选`、`Backup / 备选`、`Hold-remove / 暂缓`。
5. 决定候选款后回到原比较链接，点击`Add all to quote / 全部加入询价`，补充数量、颜色、尺码、市场、目的地及贸易条件，再提交真实询盘。

### 数据、隐私与交易边界

- PDF只使用页面已有的公开产品事实和已选择款号，不包含买家姓名、公司、邮箱、电话、数量、目标价、私密备注、管理员信息或受保护项目资料。
- 内部决定栏为空白本地评审区，网站不会把首选、备选或暂缓结果自动写入服务器；如需贝强跟进，买家仍应提交询盘或发送明确消息。
- 只有访客同意可选站内统计后，点击打印才记录`comparison_print`；事件最多保存4个规范化款号及固定页面场景，不保存PDF内容或打印结果。
- 打印次数不等于文件已保存、采购团队已审核、买家已批准、询盘、报价或订单。
- 比较PDF不是报价、采购订单、合同、Trade Assurance订单、发票、付款请求或生产授权；正式交易继续通过Alibaba Trade Assurance或双方签署的合同承接。

### 运营怎么复盘

## 73. 第六十六阶段：提交前双语采购简报完整度

### 为什么要做

后台已经能在询盘保存后识别资料缺口，但买家在提交前不知道哪些信息会直接影响首轮回复。结果可能是客户只发“请报价”，业务员再反复追问款号、数量、颜色、尺码、市场、样品和目的地。现在中英文多款询价页在填写过程中实时显示采购简报完整度与最优先补充项，把资格判断前移但不阻止人工接单。

### 买家怎么用

1. 从产品、集合、比较链接或采购指南进入`/request-quote/`或`/zh/request-quote/`。
2. 观察表单顶部的`PRE-SUBMISSION BUYING-BRIEF CHECK / 提交前采购资料检查`；它会随填写内容实时更新。
3. 优先补充面板列出的最多4项：有效联系方式、公司/市场、产品款号、逐款数量与颜色/尺码、试单或大货数量、样品决定、贸易术语、目的地、时间和其他订单要求。
4. 如确实不需要样品，可明确填写`No sample needed`或`不需要样品`；系统会把它识别为已作决定，而不是强迫填写虚假样品双数。
5. 显示“可进入首轮商业审核”后仍可继续完善；显示资料不完整时也允许提交，由业务员人工判断是否值得跟进。

### 业务员怎么解释和使用

- 分数是固定规则生成的采购资料完整度，不是AI客户画像、信用评分、欺诈判断、客户价值评分或成交概率。
- “可进入首轮商业审核”只说明背景足够支持针对性回复，不代表材料、价格、MOQ、样品、包装、库存、交期或贸易条件已确认。
- 买家提交后，后台继续使用同一套规则显示分数和缺口。业务员应一次询问最关键的1至3项，而不是把缺失项逐条分开发送。
- 不得因为分数低自动拒绝真实买家；某些首次联系资料有限但可能存在真实项目，应结合公司、渠道、产品和采购时间人工判断。

### 数据与商业边界

- 提交前计算只在当前页面内使用已有表单内容，不新增网络请求，不把未提交草稿或完整度分数保存到服务器，也不新增分析事件。
- 只有买家同意并正式提交后，询盘才按原有接口保存；正式记录、通知、查询码和后续流程保持不变。
- 完整度不是报价批准、样品批准、订单批准、付款确认或正式交易文件。最终交易继续使用Alibaba Trade Assurance或双方签署合同。

## 第七十九阶段：采购会议申请、确认与结果留痕（2026-08-28）

### 适用场景

- 2至4款候选产品需要共同评审。
- 样品范围、验收标准或修改意见需要同步澄清。
- 报价数量、包装、贸易术语和付款边界需要逐项核对。
- 技术开发买家需要区分目标、已确认能力、固定项与样品后结果。
- 正式订单承接或履约问题需要多人沟通。

### 买家怎么申请

1. 进入英文或中文私密项目页，在`Sourcing communication / 采购沟通`填写会议目的。
2. 选择视频、WhatsApp通话或电话；填写明确时区/城市，避免只写“上午”。
3. 至少给出2个、最多3个按买家当地时间填写的候选时间，写清议题和需要作出的决定；可补充参会人的职责，不在表单中填写密码、付款凭证或机密数据包。
4. 提交后状态为待审核；尚未建立日历预约，也未确认贝强人员、语言或出席。

### 业务员怎么处理

1. “今日成交工作台”会把待审会议列为内部高优先任务；进入项目的`Sourcing meetings`查看原始申请。
2. 核对时区、候选时间、负责业务员、语言支持与议题。技术开发议题先按技术型品牌买家询盘评估SOP核对证据等级。
3. 只能从买家候选时间中确认一个。视频会议使用已审核的Google Meet、Microsoft Teams或Zoom HTTPS链接；电话/WhatsApp沿用已核验项目联系方式。
4. 无法支持时填写至少5字符的买家安全原因并拒绝；已确认会议需要取消时同样写明原因。系统先保存结果，再尝试邮件通知。
5. 会后填写事实性结果：实际讨论了什么、哪些证据仍缺、双方明确的下一动作。不要把目标或口头讨论写成已确认规格、价格、样品通过、付款或订单。

### 运营复盘指标

- 会议申请数、待审时长、确认率、取消/拒绝原因、实际完成数、会后明确下一动作比例。
- 会议后是否形成完整样品范围、报价修改、订单资料或履约方案；会议数量本身不是订单或收入。
- 时区错误、议题模糊和无人负责应作为流程缺口复盘，不包装成买家低意向。
