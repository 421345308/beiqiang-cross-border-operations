# 初始化阶段：采购路径与询盘减负

## 本轮输入与边界

- 负责人说明：目前没有搜索或流量数据，网站仍在初始化阶段；不以提供数据作为继续工作的条件。
- 本轮从现有网站内容、原始产品供给边界和可检查的采购流程入手。不改阿里商品、不发布社区帖子、不生成虚构客户案例。
- 继续执行现有 GitHub main 和公开发布授权；源站与备用 Sites 均同步。

## 发现的问题与本轮改动

1. **没有选款时，报价页仍要求先加商品。** 保留多款报价的 SKU 校验，在空清单处和所有工厂/流程页补上无需款号的咨询入口 `/sourcing-review/`，中英文同步。复用已有 `sourcing_review` 询盘流程，不用假款号充当产品匹配。
2. **咨询页原先要等浏览器读取选款条件后才能显示表单。** 改为服务器直接输出首次咨询表单；浏览器选款条件仍可带入。直接访问时不替客户预填一大段采购要求。
3. **首次报价信息过重。** 将联系时间/回复偏好、品牌颜色包装调整、报价检查表折叠，明确哪些资料必填。保留表单草稿、字段值、同意选项、打印、物流和技术开发要求；展开组中的无效字段会自动显露。
4. **客户页面像内部审核材料。** 重写工厂、OEM/ODM、检查包装、样品流程中英文内容；产品模板改用“材料、尺码、配色、订单前确认”等直接表达。保留实际产品参数、逐款宽鞋头限制和交易前书面确认。
5. **客户不清楚下一步。** 解释参考链接、样品范围、费用和时间如何确认，以及提交后如何私密补充图片。保密技术文件先讨论 NDA，不把收到参考当作已确认生产能力。

## 研究依据

- [W3C 表单指南](https://www.w3.org/WAI/tutorials/forms/)建议只索取完成流程所需信息，避免不相关或过量字段增加放弃风险。本轮据此折叠选填项，而非删除验证或后台记录。
- [Google 关于生成式 AI 内容的指导](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)强调准确、相关和实际价值，批量生成无新增价值页面可能触犯垃圾内容政策。本轮改善已有采购页面，不为关键词批量造页面。

## 后续执行顺序（不依赖现有搜索数据）

1. 根据真实采购问题继续完善单款说明：哪些已知、适合讨论什么用途、看样时应检查什么；不虚构测试结果。
2. 完善批发、贴牌、产品开发三类方案间的内部链接，确保从内容页能进入相关产品和咨询，不只有泛泛的“联系我们”。
3. 围绕 MOQ 如何计算、样品与大货如何衔接、现有款改色与开模的区别，补真实可回答的内容。优先改已有页面，避免重复文章。
4. Reddit 先做问题研究和有用答复草稿，核对社区规则；不伪装买家，不在未授权情况下发帖或私信推广。
5. 有真实访问或询盘后，再看来源、入口页、开始填写到提交的变化和有效询盘质量。网站能被抓取、HTTP 正常，不等于 Google 已收录或取得排名。
