## 三、询盘与下单前转化功能

1. 单款询盘、多款询价、Line Sheet线索、人工选款、私标和技术开发使用同一询盘存储。
2. 买家最多加入12款，逐款填写数量、颜色、尺码和备注，并补充总体数量、目标市场、买家类型、目标成本、样品决定、贸易术语、目的地和时间。
3. 提交前实时显示采购资料完整度、最多4项关键缺口，并可复制或打印采购简报给团队审核。
4. 表单草稿只保存在当前标签页；正式提交前不会发邮件、写后台或计入询盘。
5. 买家可上传受控类型和大小的参考文件；服务端先验证再关联记录。当前没有自动病毒扫描，业务员必须执行隔离和线下审核。
6. 每条成功询盘获得参考号和20位私密查询码；业务邮箱接收通知，后台获得结构化记录、来源和完整度。

## 四、买家提交后的安全协作功能

| 阶段 | 买家可以做什么 | 贝强可以做什么 |
| --- | --- | --- |
| 项目访问 | 用参考号+私密码进入单项目页；用一次性邮件进入多项目工作台 | 按项目授权/撤销买家公司同事查看安全摘要 |
| 沟通 | 在同一项目发送私密消息、补充附件、申请采购会议并下载确认会议日历 | 后台回复、记录站外Email/WhatsApp/Alibaba联系、确认会议与结果 |
| 选款 | 查看业务员签发的版本化候选并选择继续、替换或暂不推进 | 从当前SKU白名单签发2–5款有证据候选 |
| 样品 | 提交样品可行性申请；在明确审核轮次中批准实物样或要求修改 | 记录样品编号、交付物、标准、排除项、费用状态、快递和历史 |
| 报价 | 查看版本化报价并接受、结构化要求修改或拒绝 | 保存不可覆盖报价快照，签发新版本并关闭旧版本 |
| 建单 | 接受报价后提交法定采购公司、联系人、渠道、PO参考、目的地和时间；审核订单准备包与八项成交前核对草案 | 人工审核资料，签发订单准备包和成交前核对草案 |
| 正式订单 | 查看核验后的Trade Assurance链接或合同参考；审核关键订单变更 | 八项门禁完整后才记录正式订单承接；关键变更必须等待买家决定 |
| 履约 | 查看付款节点记录、生产/检查/包装/发运状态、文件、异常和预计处理；提交收货反馈 | 维护买家安全进度、受控文件、异常提案和处理历史 |
| 复购 | 发起同款补单、指定款补货、新季选款或新OEM/ODM项目 | 建立新机会，不自动沿用旧价格、材料、库存或交期 |

网站中的报价接受、样品批准、订单准备和网站订单版本都是辅助证据。正式付款、生产授权和合同权利以核验后的Trade Assurance订单或双方签署合同为准。

## 五、业务员后台存量功能

- 询盘台账、搜索筛选、CSV导出、负责人、下一动作、日期、阶段和失单原因。
- 今日成交工作台：买家消息、人工选款、样品、报价、建单、订单变更、履约异常、会议和逾期动作排序。
- 买家关系提示：按有效邮箱、WhatsApp和公司名保守关联历史项目，不自动合并记录。
- 版本化候选、样品、报价、订单准备包、成交前核对草案和关键订单变更。
- 交易文件上传、买家安全下载、撤回/恢复、文件隔离和数据生命周期控制。
- 付款节点、履约阶段、物流参考、异常处理、收货反馈和复购机会。
- 7/30/90日商业漏斗、产品/来源/集合/组合信号、联系与回复SLA、销售提醒。
- 规范UTM获客链接、渠道质量、不可覆盖周报快照和中文Markdown导出。
- 管理入口：`/admin/inquiries/`；只使用EdgeOne环境中的`INQUIRY_ADMIN_TOKEN`，不得发给买家或写入源码。

## 六、日常怎么使用

### 业务员每天

1. 打开后台“今日成交工作台”，先处理买家新消息和等待贝强决定的项目。
2. 新询盘先核验公司、市场、款号、数量、样品和联系方式；一次追问1–3个最关键缺口。
3. 每个活跃项目必须有负责人、一个下一动作和日期；站外沟通只记录已经发生的事实。
4. 报价变化新建版本；样品必须绑定具体实物和审核范围；接受报价不等于订单。
5. 正式订单只在八项商业资料与Trade Assurance/合同一致后记录。

### 买家沟通时

- 不确定产品：发送选款助手或人工选款页。
- 需要内部评审：发送比较链接或中英文Line Sheet。
- 多款/私标/技术需求：进入结构化询价，不用零散邮件反复追问。
- 提交后：让买家保存参考号与私密码，在同一项目消息、传文件和做样品/报价/订单决定。
- 付款与正式生产：只引导到已核验Trade Assurance订单或双方合同。

### 每周

1. 保存周报快照，检查来源→产品/采购页→询盘→Qualified→样品→报价接受→建单→正式订单。
2. 与真实Alibaba/合同/财务记录核对订单和付款，不把网页点击当成交。
3. 用Search Console真实查询和买家问题决定内容、产品证据和获客页面优先级。

## 七、当前没有完成或设计上不在站内完成

1. 正式域名TLS和EdgeOne自动生产部署仍未完成最新版本验收。
2. Search Console所有权、sitemap接收、页面收录和真实查询数据尚无完成证据。
3. 真实询盘的SMTP收件、后台读取、买家回执、状态页、回复与清理全链路仍需明确标记的内部测试。
4. 产品事实仍需按真实数据包继续补齐；BQ014/BQ020仍无单款Alibaba商品ID。
5. 自动恶意文件扫描、正式法律审阅、生产删除密钥职责和自动定时提醒仍需外部或人工配置证明。
6. 网站不收银行卡或银行账户凭据，不取代Alibaba Trade Assurance、合同、财务、物流或争议系统。

## 八、以后新增产品或功能的发布门禁

1. 产品必须先核对唯一身份、重复/IP风险、图片和SKU级事实。
2. 更新产品源后运行`npm run catalog:sync`、`npm run line-sheet:build`、完整测试、EdgeOne导出和lint。
3. Line Sheet清单会核对产品事实哈希、产品数、页数、PDF大小、英文/中文文件哈希和公开/运营副本一致性；测试失败不得发布。
4. PDF必须全部渲染为PNG并逐页检查中文、截断、重叠、图片、页码和CTA。
5. 发布必须记录GitHub提交、Sites/EdgeOne版本、部署ID、线上页面/PDF状态及未完成边界。
6. 每次客户可见发布都更新`app/data/site-release.ts`，并运行`npm run verify:deployments`；正式域名和备用站必须返回同一`releaseId`、56款口径、180秒视频及英/中字幕资源。

## 九、部署防漂移门禁（2026-09-03）

- 当前发布指纹为`2026-09-03.3`，公开入口为`/release.json`；只含版本号、发布时间、产品数、Line Sheet页数和工厂媒体规格，不含密钥、买家或后台数据。
- `npm run verify:deployments`同时检查`www.beiqiang.online`与Sites备用站。首页HTTP 200不再等于发布成功；版本缺失/落后，或完整视频、英文字幕、中文字幕任一不可读，均判定失败。
- 本轮备用站第65版在线通过：发布指纹、180秒MP4、英文VTT和中文VTT均为HTTP 200且内容类型正确。

- EdgeOne修复必须在腾讯云登录状态下核对：GitHub仓库授权、生产分支`main`、根目录`edgeone-deploy`、安装命令`npm ci --prefix ..`、构建命令`npm run build`、输出目录`dist`、自动生产部署开关及最近失败日志。

- 中英文产品页、采购指南和多款询价页现统一展示四项项目初筛参考：线上采购起点`2双`、适合项目的大货FOB目标带`8–12美元/双`、`100双/31天`时间参考、单双`34 × 23 × 13厘米/0.5千克`包装参考。
