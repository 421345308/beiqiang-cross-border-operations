# 贝强项目记忆系统

唯一项目记忆库；只保存未被 `AGENTS.md`、SOP、业务状态或项目记录覆盖的已确认决定与有用经验。

## 按需读取

1. 每项任务先读本页和 `INDEX.md`；同一任务已读且未变更的文件不重复读取。
2. 先由根及专项 `AGENTS.md` 获取身份、事实和授权边界。按任务对象和 `scope` 筛选索引，排除已替代或有争议条目，再读必要正文；普通工具任务不加载公司背景。
3. 历史日期不是当前状态。涉及库存、平台、客户、实例、价格或进度，直接核验正文所指业务源；没有新证据时写“最近确认”，不得自动改成今天已验证。
4. 只简述实际影响决策的记忆。对外输出不泄露内部条目；不要全库读取或复述。
5. 全库审计仅在用户要求整理、检索冲突或排查污染时执行。

## 读取判断

| 类型 | 判断依据 |
| --- | --- |
| Authorization | 用户对具体动作、对象和边界的授权；不能转给新对象或新动作 |
| Preference | 用户在适用范围内的明确选择；项目例外与当次要求优先 |
| Decision | 已确认的持续决定；动态进度和平台状态仍须实时查业务源 |
| Experience | 有条件、有证据的经验；辅助选择，不自动成为命令 |

先判断任务和对象是否落在 `scope` 内，再看 `status`、`supersedes` 和复核条件；随后按类型核验来源，最后处理同范围的更新与冲突。新总结的日期不覆盖原始证据，复核日期届满不使结论自动失效。`source: pending` 表示原始确认记录未定位；尤其不能据此扩大外部发送或付费授权。记忆不覆盖用户最新指令，冲突回查原始来源。
只创建实际有内容的分支。正式记忆固定为 `一级/二级/文件.md`，二级目录只放文件；存在的目录保留简短 README。

## 写入与清理

- 日常新增事实、归类或晋级：先列候选、来源、适用范围、归属、隐私及排除理由，取得确认后写入并同步索引。AI 输出和普通对话不自动入库。
- 用户已明确要求整理、合并、删除过时记忆时，授权范围内直接执行，不重复请求确认；不能借整理新增未经确认的事实或把经验晋级为规则。
- 同一事实只保留一处正文，其余使用入口。SOP、命令参数、SKU/CRM 状态留在原业务源。
- 只删除已确认无效或已完整合并的记忆；原件、客户记录和有效执行证据不因年代旧而删除。不为无用内容新建备份。
- 同步修复索引与活动引用；删除前核验绝对路径在授权目录内。
- `timestamp` 保留事实/偏好最近确认日期；仅整理格式不刷新日期。已失效且无剩余价值的条目删除；仍有必要保留的历史经验明确适用范围。

正式记忆使用以下十个必填字段；额外字段只在确有用途时填写：

```yaml
---
id: stable-lowercase-id
type: Authorization | Preference | Decision | Experience
title: 简短标题
description: 何时读取及解决什么问题
status: active | superseded | disputed | archived
scope: 实际适用业务、任务、项目、SKU 或工具版本
source: 仓库相对证据路径 | pending
privacy: internal | public
tags: [主题]
timestamp: YYYY-MM-DD
# 按需：supersedes: 被明确替代的旧 id
# 按需：verify_when: 何时重查实际来源
# 按需：review_after: YYYY-MM-DD
---
```

`id` 与文件名、日期无关，移动文件时不变。`source` 写真实存在的仓库相对路径；尚未找到原始确认记录时用 `pending`，不得编造路径或对话 ID。`supersedes` 只指向仍保存的旧条目；旧条目标 `superseded` 并退出默认索引。`disputed` 和 `archived` 也不参与默认读取，但保留必要追溯。索引是发现入口，正文元数据为唯一可编辑事实；维护检查验证两者一致。
