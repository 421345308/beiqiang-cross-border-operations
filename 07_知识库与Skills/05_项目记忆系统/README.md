# 贝强项目记忆系统

维护日期：2026-09-11。唯一记忆库；保存稳定判断和证据入口，不复制业务台账。

## 按需读取

1. 每项任务先读本页和 `INDEX.md`；同一任务已读且未变更的文件不重复读取。
2. 按索引任务信号筛选。涉及公司事实先读相关身份基线，再按 L1 → L5 读取必要正文；普通工具任务不加载公司背景。
3. 历史日期不是当前状态。涉及库存、平台、客户、实例、价格或进度，直接核验正文所指业务源；没有新证据时写“最近确认”，不得自动改成今天已验证。
4. 只简述实际影响决策的记忆。对外输出不泄露内部条目；不要全库读取或复述。
5. 全库审计仅在用户要求整理、检索冲突或排查污染时执行。

## 分类与权重

| 类别 | 用途与权重 |
| --- | --- |
| identity | 公司身份与长期方向；提供事实背景 |
| principles | behavioral-rules / business-boundaries 为 L1；decision-making 为 L2 |
| preferences | 协作与交付偏好，L3 |
| context | 最近确认的项目状态与原始入口，L4 |
| knowledge | skills 为 L2；experiences / learnings 为 L5，仅作有范围的参考 |

高权重不覆盖证据或用户最新指令。发现冲突回查原始来源，用户保留最终决定权。
只创建实际有内容的分支，不为五类或权重填充模板。正式记忆固定为 `一级/二级/文件.md`，二级目录只放文件；存在的目录保留简短 README。

## 写入与清理

- 日常新增事实、归类或晋级：先列候选、来源、归属/权重、隐私及排除理由，取得确认后写入并同步索引。AI 输出和普通对话不自动入库。
- 用户已明确要求整理、合并、删除过时记忆时，授权范围内直接执行，不重复请求确认；不能借整理新增未经确认的事实或把经验晋级为规则。
- 同一事实只保留一处正文，其余使用入口。SOP、命令参数、SKU/CRM 状态留在原业务源。
- 只删除已确认无效或已完整合并的记忆；原件、客户记录和有效执行证据不因年代旧而删除。不为无用内容新建备份。
- 同步修复索引与活动引用；删除前核验绝对路径在授权目录内。
- `timestamp` 保留事实/偏好最近确认日期；仅整理格式不刷新日期。已失效且无剩余价值的条目删除；仍有必要保留的历史经验明确适用范围。

正式记忆恰好使用以下七字段：

```yaml
---
type: Identity | Principle | Preference | Context | Skill | Experience | Learning
title: 简短标题
description: 何时读取及解决什么问题
status: active | archived
privacy: internal | public
tags: [主题]
timestamp: YYYY-MM-DD
---
```
