# 视频参考资产与镜头准备

适用：需要同一角色、动物、商品、道具或空间跨镜头持续出现的 AI 视频。普通海报、单幅插画、数学图解不强制做整套资产。负责人于2026-10-13明确要求将本片暴露的资产准备缺口整合进项目能力；下面是已采用的制作方法，不是模型已获得新训练能力或成功率承诺。

## 先区分交付物

| 类型 | 负责的信息 | 不自动继承 |
| --- | --- | --- |
| 人物/动物身份 | 面部或毛色、体型、可见比例、多角度特征 | 房间、原姿势、光线、宫格或标签 |
| 服装/穿戴状态 | 单品、配色、剪裁、图案位置、实际穿戴方式 | 任意换装；动物不因此获得人手或人的骨架 |
| 商品原件 | 真实 SKU、颜色、可见结构与商品身份 | 隐藏面推测、实物性能、库存或材料证明 |
| 道具结构 | 同一物体正/背/侧、尺寸关系、支架/关节 | 不同视角变成不同物体；屏幕自动朝镜头 |
| 空景 | 家具、门窗、路径和空间关系 | 每镜头同机位；白天素材锁死夜间光线 |
| 镜头组合图 | 当前动作状态、站位、视线、接触、画幅与景别 | 自动成为身份源或视频首帧 |
| 首帧/关键帧 | 被选定的单幅动作起点/时间状态 | 宫格、审阅标签或多个角色替身 |

先建立资产，再按镜头组合。身份、商品和地点原件不因组合时修改姿势而被改写。

## 根据镜头决定多视图

- 人物有明显转身/侧脸/遮挡时，补前、侧、后等必要视角及可读的脸部参考；不把固定“四视图”当所有任务的最低数量。
- 动物要核毛色/额鼻纹、耳形、躯干、四足、尾部及服装的正背面；图案位置不能为方便可见而移动。
- 商品缺少某角度时先寻找原始图。生成出来的隐藏面可作候选设计，不能升级为实物证据。
- 角色跨镜头换鞋/换衣时，在镜头状态里声明变化。基础身份图可用中性穿戴状态；“人物一律白袜”不是通用要求。
- 宫格用于审阅/身份时，明确多个视角属于同一主体。若实际入口/主体数量让宫格含义不清，按需要另取独立角度图；不无目的增加参考数量。
- 道具对向、折叠、接触有作用时补结构视角；不为只出现一次的普通无标物体强制做多视图。

## 当前包与输入职责

每个视频项目保持一份当前 asset manifest。支持下述字段；既有项目可兼容迁移，不为改格式重建所有媒体：

- project-relative 文件基准；
- selected_assets：唯一 id、file、role、输入来源、inherit/exclude、完整 prompt、尺寸和sha256；
- input_only_sources：还用于追溯/再生成的原件，不作为默认输入；
- product_reference：真实商品图及证据入口；
- continuity：全局身份/穿戴/道具规则，允许按时间状态变化；
- 被替换、删除的图退出 selected_assets，修消费引用后删除无用副本；不保留多份“当前版本”。

角色图、空景、动作视频与声音分别编号。正式上传后以入口实际顺序校对编号；内部语义 id 不假装是 Provider 原生token。提示词说明取什么、排除什么，避免逐字复述精确原图与其发生冲突。

## 组合镜头与自审

组合前在 shot manifest 中写清：

- id、time_range、purpose、file、reference_ids、prompt；
- states：本镜出现谁、衣服/鞋、地点、时间和道具；
- action_start/action_end：动作从何时开始，产生什么可见结果；
- visual_review：当前图的passed/needs_repair和具体发现，不能用期望值冒充像素观察；
- 如有特定结构限制，constraints 中明确角色/物体的状态规则，例如“此镜鞋必须是旧鞋”“狗背心全片相同”。

从实际图检查：同一张脸与体型，动物毛色与衣服位置，腿/爪/手数量，商品两只鞋与鞋底结构，人物—道具比例，视线及接触点，屏幕正背、空间动线、光线、时间阶段。发现问题只修相关状态，回看修改有没有引入新错。审阅宫格或母版输入不直接设置为first_frame。

商品图负责真实结构，组合图负责镜头安排；二者冲突时以商品原件为准。需要核纹理或部件时，让商品在构图里足够大、角度可读，不能由模糊远景宣称细节已准确。多次局部修改仍不稳定时，重新设计可读的景别/视角，或如实留待修项，不重复填通过。每次改图都重查先前正确部分，尤其接触点、脚/爪和商品结构；改对一个部件不代表其余仍正确。

开箱、穿鞋或点屏等过桥动作有必要起止；静态关键帧只验收图的起点，不验收完整动作。付费视频仍须连贯动作与声音审看，不能由“图通过”推断视频已可用。镜头图可以留必要创作自由，不为每一秒生成一张图。

## 可执行检查

工具：[validate_reference_assets.py](../../../../08_工具链/02_视频工具/资产准备/validate_reference_assets.py)。

首次执行看 --help。检查 asset manifest：

    python validate_reference_assets.py <assets.json> --project-root <PROJECT.md所在目录>

再检查组合镜头：

    python validate_reference_assets.py <assets.json> --project-root <项目目录> --shots <shots.json>

程序检查文件可读、尺寸/哈希与记录一致、唯一ID/当前文件、继承/排除职责、镜头引用、连续性条件和审核字段。返回0只代表这些结构检查通过；它不看像素，不把图合格/防变形/审美或付费授权判为通过。失败先修真实缺口，不伪填passed。

## Seedance资料边界

2026-10-13核官方[2.5提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)：支持身份/场景/动作/故事板/关键帧等不同参考用途；单/多视图选择应随主体数量与任务变化。具体参数每次由所选版本官方资料与实际Provider schema核对，不从本页固定30张、30秒等跨版本默认。

[公开案例参考模板](https://github.com/LearnPrompt/awesome-seedance/blob/main/docs/templates/zh/character-reference-lock.md)展示身份、服装、地点分工及排除原背景/构图/光线的写法。它是创作者经验，不能代替独立效果验收。本片发现的平板朝向、旧/新鞋和狗背心问题是项目特定的连续性检查，不升级为所有视频都必须出现这些物件。

商品原件、媒体、平台上传、付费、验收与发布仍按根/视频入口和项目权限执行。选择模型或继续准备图片不是新增付费视频授权。
