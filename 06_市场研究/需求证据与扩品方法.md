# 需求证据与扩品方法

用于决定选什么鞋、补哪些网页和内容、去哪类市场获客。具体观察放对应研究或产品对象，产品事实仍以产品中心及原始证据为准。窄范围请求只执行相关步骤，不把本文变成每次操作的全套门槛。

## 不同数据回答不同问题

| 数据 | 可以回答 | 不能直接回答 |
| --- | --- | --- |
| Google Trends | 某市场、时间内的相对搜索兴趣、季节性、相关查询 | 绝对搜索量、成交量、利润、某款鞋一定能卖 |
| Search Console | 本站获得哪些查询展示、点击，哪些页面有机会 | 整个市场需求量；本站未曝光的需求不存在 |
| 关键词规划工具 | 指定地区的估算搜索量、广告竞争等 | 实际销量或自然搜索难度的完整结论 |
| 有范围的零售销售报告 | 报告渠道、时期和样本中的成交、份额、增减 | 全国/全球市场占比，贝强相似鞋的销量 |
| 品牌财报 | 该品牌已披露的收入、区域或品类表现 | 每款销量，增长由某个鞋型或功能造成 |
| 电商榜单、购买提示、评价 | 当时页面的排序或提示，以及消费者表达 | 未披露周期的月销量；评价数等于订单数 |
| 国际站询盘、RFQ | 真实采购需求、数量、市场和规格 | 所有零售消费者偏好，未成交询盘等于订单 |
| 社媒观看、收藏、评论 | 注意力、内容反馈、用户问题 | 转化、采购意愿或盈利已成立 |
| 搜鞋网商品和拿货入口 | 实款、供应商、可核对采购路线和当时公开条件 | 人气等于销量；页面库存等于已确认履约；外采等于自产 |

搜索结果数量、供应商数量和标题重复度至多描述观察到的供给，不能作为市场需求量。记录“缺少数据”不允许继续称“爆款”“蓝海”或“卖得最好”。

## Google Trends 的使用

先写清决策与地区，再确定查询词或主题。美国、英国、德国、法国、西班牙分别观察；不同国家指数不直接比较市场规模。德法西用本地采购/消费者表达，不能仅把英文词放进所有市场。

- 5年窗口看长期方向和季节性，12个月看当前结构，90天看近期变化；把未结束的日期段与完整区间分开。
- Web Search 与 Google Shopping 分开记录；同图比较保持地区、期间、类别、搜索类型一致。术语与主题的覆盖不同，不混成同一口径。
- 指数0—100是归一化相对兴趣，不是搜索次数；低量词显示0不能判定无需求。不同查询批次各自的100不能直接相除作为市场份额。
- 分批必须保留共同参照词及一致设置；低量、抽样和时间粒度变化都影响稳定性，不从一两个点推导增长率。
- 保存查询链接、导出CSV、观察时间、查询设置、数据窗口及缺失说明。相关上升查询可能来自新闻、促销或低基数，须回查意图。
- 消费者词用于理解鞋型与需求；供应商、wholesale、private label、OEM等采购词用于选承接页。不能因消费者词大就批量创建B2C评测文章吸引不匹配流量。
- 访问限流或工具不可用时记录实际错误，不绕过、不编造数值。继续用可用的独立证据研究；数据恢复后补充会影响决策的对比。
- 区分HTTP429、浏览器导航超时、登录失败与连接工具订阅到期。直接请求受限后可用正常浏览器检查页面是否可读；导航超时先查看原标签实际状态，避免重复刷新。正常页面可用时通过官方CSV导出留证；仍受限则停止重试并记录，不能通过代理轮换或绕过验证码取数。
- 替代来源各司其职：[Google关键词规划师](https://support.google.com/google-ads/answer/7337243?hl=en)补估算搜索量/广告竞争，[Microsoft关键词规划师](https://help.ads.microsoft.com/apex/index/3/en-us/50902)补其搜索网络信号；均需相应账户条件，不能混成同平台销量。Search Console用正式界面或已授权官方API读取本站查询，不依赖某一个付费连接工具。第三方工具先核数据出处、更新时间、授权及费用，不将“可以调用”当作数据准确。
- [Google Trends官方API](https://developers.google.com/search/apis/trends)截至2026-10-25仍为需申请的alpha，不默认已获访问权限。缓存同设置的导出，按决策需要更新；不得把网页指数与API不同缩放方式的数据直接拼接。

方法依据：[Google Trends数据说明](https://support.google.com/trends/answer/4365533?hl=en)，2026-10-25核验。Google说明其数据为抽样和归一化的搜索兴趣，应与其他信息结合。

## “卖得好”和“为什么”的判断

先标明报告主体、发布日、销售期间、地区、渠道、款/品牌、金额/双数以及分母。把大份额与快增长分开，不能将小基数增长率当作主流规模。自营零售商数据有选品、门店分布、供货、推广和价格结构偏差。

将结论分成直接观察与解释假设。例如“某零售商的宽鞋头品牌增长”是观察，“消费者更重视脚趾空间”可能是解释，但渠道增铺、促销、缺货恢复也可能影响增长。优先用具体买家问题、评价主题、查询和多个渠道的销售资料交叉核对；不要用竞品营销理由替代因果证据。

品牌技术、专利结构、医疗功效、专业运动表现与外观鞋型分开。研究缓震或易穿脱需求，不代表可以为贝强所有厚底或套脚鞋写相同性能。需求结论不改变产品事实。

## 从需求到搜鞋网选款

1. 先对账现有产品中心、网站和渠道：哪些实款已经有，哪些只是不在官网，哪些是历史草稿。保留同一产品身份，不为了新渠道重复建款。
2. 明确产品缺口：用途、结构、配色/尺码范围、目标买家和差异。先补独立产品角色，避免只换标题或颜色制造大量近似页面。
3. 在搜鞋网找真实产品与有效采购入口，记录供应商、原款号、链接及日期；逐款核图，排除详情里的其他推荐款。网站公开数据不直接带入内部采购成本和源链接。
4. 区分来源成立、规格已知、订单条件和可发布素材。缺材料只限制材料声明，缺精确库存不等于不能提供咨询展示；报价/发货按订单确认。没有真实鞋或有效来源时保留HOLD_SOURCE。
5. 外采产品可以作为贝强供应范围展示；制造商和工厂介绍不能错配。转自产须负责人明确确认。不得把“只接受自有工厂货”或“所有款先买实物样品”另设为通用条件。
6. 选款优先级结合需求证据、现有供货、页面准备度、订单费用和买家匹配。成本加价不是净利润；报价规则只回当前渠道及单款已确认记录。
7. 发布前核独立详情、图片与色码对应、语言版本、分类、搜索数据和询盘可识别该款。站内页面出现、平台成功、正式域名可见和实际成交分别记录。

## 知识与渠道职责

| 内容 | 唯一维护位置 | 其他渠道如何使用 |
| --- | --- | --- |
| 产品身份、供货关系、原件及事实 | 产品中心与对应原始证据 | 按ID引用，按渠道选择公开字段 |
| 需求研究与证据解释 | 市场研究对应主题 | 引用结论、地区和时间范围，不复制成产品性能 |
| 官网结构、搜索、多语言及表单 | 独立站SOP与源码 | 独立详情承接不同渠道的访问 |
| 国际站发布、报价、P4P及字段回读 | Alibaba运营SOP与单款档案 | 不强加到官网和社媒 |
| 社媒内容及获客 | 相应社媒入口与内容项目 | 按实际受众选择内容和联系路径 |
| 实际询盘与客户推进 | 原CRM/客户项目 | 只回传可公开的汇总，不散落客户原件 |
| Skill | 简明执行路由与判断规则 | 链接权威SOP，不重复存放价格、当前优先级和产品事实 |

修改旧知识先定位矛盾或失效依据，修正原入口和实际调用的参考文件。保留有效事实、历史授权与原始证据；不以模型版本为由全量重写。检验窄任务不会被放大、外采不会被误判、渠道动作不会被固定模板绑住。
