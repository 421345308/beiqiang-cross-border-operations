# 客户发现助手 · 产品使命与当前决策

更新：2026-10-22。这里维护产品负责人的使命、当前问题、证据与验收；使用方法和已实现能力仍见 [README](README.md)，客户事实回[客户开发入口](../../../04_客户开发/README.md)，产品事实回[产品中心](../../../00_总控台/产品中心/README.md)。不在这里保存客户身份、原始消息或账号凭证。

## 使命与工作方式

减少负责人查企业、辨别采购角色、重复核对历史及决定下一步的负担，让合理账户进入可追溯的采购讨论。发现量、采集量、发布量、发送量和程序测试数不能代替真人回复、转交采购、报价或样品进展。

产品与研发使用独立上下文，互相挑战后协作交付。负责人不必逐项发现问题或写需求：产品岗每轮主动选择最重要的未解决问题，查真实工作流及一手来源，提出取舍；研发岗判断技术、数据和维护成本，指出不能成立的前提。角色在被启动的会话内工作，不是常驻后台或24小时自治团队；跨轮从本入口重建当前结论，普通历史交给Git。

| 角色 | 对什么负责 | 每轮交接的最少内容 |
| --- | --- | --- |
| 产品负责人 | 主动找遗漏问题、验证是否值得做、界定实际价值；可拒绝只增加忙碌的功能 | 真实任务与摩擦、来源/日期、事实与假设、要验证的一件事、验收及转向条件 |
| 研发负责人 | 实现可用功能，独立质疑数据可获得性、故障恢复、成本、方案复杂度 | 可行与不可行部分、实现取舍、运行证据、已知限制；不能用代码存在证明有效 |
| 独立验收 | 根据产品验收重放任务、反例和故障；实现者不得自签产品验收 | 通过/不通过/尚未证明、可复查证据、阻断与非阻断问题 |
| 协调负责人 | 裁决产品与研发分歧、保护范围与数据、对用户结果负责 | 采取哪项结论及原因，只把真实必要的用户决策上交 |

研发发现数据源不支持、实现收益低或产品假设有反例时直接找产品讨论；产品不能用“先做出来”跳过取证，研发不能以“能写脚本”替代需求判断。对外发送、购买服务和改动平台权限仍按原授权范围执行，本页不新增授权或定时任务。

## 当前真实工作流与三个遗漏需求

2026-10-22核读了当前 `app.py`、`core.py`、`index.html`、README、原流水线SOP及渠道方案；本轮没有外发。现有工具已能导入企业官网、有限页采集、入口用途区分、留原文证据、保存研究判断及导出。联网发现仍主要由会话搜索或人工搜索完成；工具不是自主全网搜索服务。

| 优先问题 | 已观察到的缺口 | 产品判断与最小推进 |
| --- | --- | --- |
| 1. 一家企业是否已联系、当前该接哪一步 | `app.py` 的状态与导出要求负责人再到正式CRM查重；本地候选ID与正式Lead ID断开。研究判断只有“值得继续”等状态，不能表示联系结果 | 先复用正式CRM做只读核对，把历史与未知项放回同一张候选卡。减少反复打开工作簿和重复研究，保护停止联系状态 |
| 2. 数据路线是否真的可持续、找到的是买家还是卖家 | 未验收方案把海关渠道称近零成本、高收益，并把参展商名录视为买家来源；`discover.py` 用网页接口与页面结构取数，注释把robots放行当作依据。官方资料推翻了部分前提 | 每个来源先核允许的访问方式、覆盖、时效、费用及角色，再接入；供应商/品牌名录、历史进口与当前采购需求分别标明。不先扩大采集量 |
| 3. 研究怎样变成有下一步的采购讨论，并反过来改进筛选 | 当前工具没有结构化的机会假设、下一动作及真实结果回收；关键词初筛不能替负责人决定该问采购负责人、产品方向还是数量目的地 | 下一阶段从一张“行动依据卡”连接已有证据、CRM阶段、匹配方向和一个最小问题；真实发送与回复留原CRM，再用结果改筛选。先核历史结果是否可回收，不另建CRM或自动外发序列 |

这里不预设“小客户一定无价值”或“大进口商一定适合”。代发也是用户确认可探索的业务，但订单经济性须按目的地、数量、供货版本和履约条件核对，不能用公司体量代替判断。尚未精确对应SKU的合理邻近账户可以保留；承诺具体供货前须映射已核来源的SKU。

## 当前一项可交付闭环：官网候选 → 正式CRM只读核对 → 明确接续位置

本轮优先做这一步，因为已有真实候选和CRM，不需要购买数据或等待平台接入；先消除负责人每次研究都要重复找历史的操作。它是完整获客链路中的可验证阶段，不声称已带来采购回复。

研发任务：在现有候选详情、CLI/本机接口和CSV中展示正式CRM的精确匹配结果及证据。不修改CRM，不新增一套客户状态库，不自动联系。

结果最少包含：

- 规范化企业域名或明确邮箱的精确匹配方式、全部匹配Lead ID及来源工作表/行；不同Lead冲突保留，不做公司名模糊自动合并。
- 最近有依据的触达、下一动作及其实际字段来源；仅计划/草稿不可显示成已发送、送达或已回复。
- 停止状态区分明确停止、技术暂缓、品类不匹配、无效入口、时机暂缓及未知，并保留原始原因。独立验收岗核到真实 `Stop / opt-out` 列含 `TECHNICAL_GATE`、`EMAIL_INVALID`、`CATEGORY_MISMATCH`、`PAUSED_NOT_NOW`，不能一律称客户退订；这些限制也不能变成“可联系”。空值、否定语义、缺字段和多来源冲突不武断归类。候选自身已停止状态继续生效。
- 核对时间、工作簿hash/更新时间、读取覆盖与故障；结果过时或工作簿不可读时显示未知，不能继续展示为最新确认。
- 未匹配只表示“本文件未匹配”，不能称新增买家、无人联系或可以发送；核对成功也不等于覆盖全部渠道/客户项目或获得接收同意。

### 用户任务与独立验收

目标任务是“打开一个研究候选，直接知道应回哪个既有客户记录、有哪些历史事实和还缺什么”，无需为这一步重新手搜整本CRM。产品先用真实文件核schema，验收用本地匿名编号留证，不公开客户原文。

| 场景 | 通过标准 |
| --- | --- |
| 精确域名/邮箱命中既有客户 | 详情和CSV保留正式Lead ID及工作表/行依据，可回原记录；保留人工研究状态 |
| 停止或其他门禁 | 直接可见原始依据，区分退订/停止、技术、品类、无效入口和时机；不生成建议发送或“可联系”结论；CRM和候选原状态未被覆盖 |
| 未匹配、缺字段/文件、冲突或读取失败 | 可辨别是哪一种未知，不伪装成无历史、已清理或允许联系 |
| 历史动作 | 计划与实际分开，日期及状态能由原字段复核；无证据不补造最近触达 |
| 数据保护 | 工作簿处理前后hash一致；客户内容只留忽略目录/本机响应，公开Git仅代码、方法、匿名测试数据 |

实现者完成程序检查后，交独立验收者从用户任务重新操作并核反例。当前状态：**正式CRM只读核对小闭环已通过独立数据与接口验收**。真实6个候选中3个精确匹配既有Lead（2个域名、1个完整邮箱），关联3条日志；另3个未匹配，停止状态均为未知，不能据此认定新增客户或允许联系。原CRM前后SHA256一致。

独立验收重放了HTTP状态到CSV、文件删除后不复用旧结果、8组独立构造的工作簿反例；当前36项程序检查通过。列表CRM标签、详情原始下一动作/状态/结果及本地停止提示已接入。以上证明历史核对阶段可用，不证明官网发现准确率、采购意愿或触达效果。

尚未完成浏览器视觉与真实点击验收，没有本轮发送、送达、真人回复或采购推进证据。首次测试曾出现一次临时文件替换 `WinError 5`，原始锁来源未确证。研发已增加唯一临时文件、有限退避与明确HTTP 503失败；独立验收用Windows真实文件锁验证持续锁定时旧JSON不变、临时文件清理，短暂锁释放后准确保存。该故障类别的恢复和失败保护已验收，不代表所有保存故障均已解决。

## 下一轮由产品岗主动推进

每次启动先看真实任务：本轮用户是否仍需重复查历史、有没有已触达对象的未处理回复、候选为何无法形成下一步。先抽看少量本地记录与最新失败，按“负责人重复劳动/采购机会损失、证据强度、可验证成本”选一个最大瓶颈，不能只是继续上轮代码待办。

只读核对的数据/接口验收已完成；下一轮产品先检查历史触达与回复是否可可靠回收 → 若可回收，准备一张基于既有账户的行动依据卡；若不可回收，先解决结果记录断点。产品主动补官网/官方渠道证据、与研发讨论，不等负责人列字段。新渠道发现只在现有账户无法形成可验证机会、或有明确更强新信号时优先投入。

每轮交付必须回答：替负责人减少了哪一步、能否复现、还有哪个假设未被证实、下一步为何值得做。使用真实任务记录人工操作步骤与耗时，未测不宣称节省百分比；业务效果另看真人回复、采购转交及报价/样品推进。

停止/转向条件：

- 数据源不允许当前访问方式或费用未核：停止该接入，改评估许可/API/已有授权导入，不换隐蔽通道。
- CRM字段不能可靠映射或证据冲突：只展示未知与来源，先修清晰的字段/核对问题，不扩大自动判断。
- 验收后负责人仍要重新搜同样资料才能决策：该功能产品验收不通过，修复信息与接续断点后再加功能。
- 连续真实任务显示某来源仅有卖家、旧需求或无承接能力：调低投入，研究另一条机会路线；没有分母与结果归因时，不宣布整个渠道无效。
- 没有发送、送达及回复证据：只承认研究阶段完成，不承诺获客效果；不靠扩大账号或发送量填补证据空白。

本轮不做账号购买、隐藏关联、绕过登录/限制、陌生人批量私信、自动外发、新建CRM、付费数据采购或新定时任务。正常授权多账号管理不是本轮优先交付；未来若有真实业务需求，按身份、权限与平台支持能力单独评估。
