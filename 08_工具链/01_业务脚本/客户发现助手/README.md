# 客户发现助手

贝强自用的海外企业发现、公开商务入口采集与证据核验工具。负责人2026-10-21选定：优先精准客户和建立联系，不建设社媒矩阵发布。首版负责发现到研究，不执行外发，不自动把候选升级为采购商机。

## 使用

Python 3.11+，仅标准库，无需购买新服务或安装依赖。在工作台根目录运行：

```powershell
python -X utf8 '08_工具链/01_业务脚本/客户发现助手/app.py' serve
```

打开 <http://127.0.0.1:8766>。可选择市场生成搜索路线、添加官网、导入搜索候选、勾选企业核查、查看原始出处、保存人工核验、导出研究CSV。界面只在127.0.0.1监听；不要通过代理或端口转发公开访问。

发现有两条真实路线：

- 在Codex中提出市场/产品/买家类型，由现有联网搜索发现企业官网，整理为下面的JSON导入。搜索摘要只作发现，联系方式和判断仍回官网取证。
- 工作台生成搜索链接，负责人打开搜索后添加官网。此按钮只生成搜索路线，不是假装已接搜索API的自动找客。

首版没有独立后台全网搜索服务，不接付费数据库。自然语言搜索复用当前Codex联网工具；后续是否需要无人值守搜索，根据真实使用量决定。

```json
{
  "candidates": [
    {
      "company": "Synthetic Example Footwear",
      "website": "https://company.example/",
      "market_hint": "United Kingdom（搜索阶段线索待核）",
      "source_url": "https://company.example/about",
      "discovery_note": "待从官网核实鞋类业务和采购角色",
      "pages": ["https://company.example/contact"]
    }
  ]
}
```

以上为虚构格式例，不是真实买家。批量导入最多100家、每轮采集最多20家、每家1至8页。命令行也可使用：

```powershell
python -X utf8 '08_工具链/01_业务脚本/客户发现助手/app.py' plan --market 'United States' --direction 'comfort casual footwear'
python -X utf8 '08_工具链/01_业务脚本/客户发现助手/app.py' import '04_客户开发/02_目标名单/.local/客户发现助手/search_candidates.json'
python -X utf8 '08_工具链/01_业务脚本/客户发现助手/app.py' scan --max-pages 4
python -X utf8 '08_工具链/01_业务脚本/客户发现助手/app.py' export '04_客户开发/02_目标名单/.local/客户发现助手/候选研究.csv'
python -X utf8 -m unittest discover -s '08_工具链/01_业务脚本/客户发现助手' -p 'test_*.py' -v
```

## 怎样判断“精准”

分别显示鞋类/休闲方向、分销/品牌/零售角色、供应商申请或公开寻源表述，每项附官网原文和URL。规则初筛可解释、可人工纠正；不是AI自动背调、采购确认或概率评分。市场字段只是发现线索，不能从.com或搜索关键词推断公司所在地。

批发商往往正在向零售商卖货；批发账号申请不代表向贝强采购。工具将采购相关邮箱、销售邮箱、客服、供应商申请、经销申请分别标注。供应商申请也可能只服务现有供应商，须核用途和时效。含制造/寻源业务时提示区分采购方与同行；专业性能品类不能自动套用贝强能力。

产品邻近、系列补充和备用供应机会继续遵守[主动获客流水线SOP](../../../../04_客户开发/01_线索与CRM/规模化主动获客流水线SOP_2026-09-17.md)，不要求每家已卖同款。不从客户页面推导贝强材料、宽楦、认证、库存或供货承诺。

## 联系与数据边界

- 只读取企业公开HTML页面；按站点robots与采集间隔执行。遇到401/403/429、验证码、跨企业跳转或无法核实的robots策略，停止或留待人工处理。不能绕过登录或平台限制。
- 不采集社媒群成员、非公开个人信息、隐藏脚本联系人或猜测邮箱。联系方式仅来自正文、明确mailto/tel、公开WhatsApp链接及相关表单；不验证邮箱投递能力，不发送探测邮件。
- 公开入口不等于营销同意。企业采购/供应商入口优先核用途，销售和客服只作转交路径候选；WhatsApp需满足接收同意等当前规则。企业邮件仍受收件方过滤与适用规则影响，无法承诺“不被管控”。
- 客户资料、原文证据、搜索候选、研究状态和导出全部留在 `04_客户开发/02_目标名单/.local/客户发现助手/`，受现有Git忽略规则保护。外部网页正文仅以不可执行JSON保留，不在本地运行。
- 此处为候选暂存区，不是第二个CRM。候选ID由官网域名稳定生成，只用于暂存去重；正式CRM Lead ID、历史发送、拒绝/退订仍回[客户入口](../../../../04_客户开发/README.md)核对。首版不会改现有工作簿，也不会读取旧表后推断今天可联系。
- “停止联系”阻止该候选再次采集，人工状态不会被重新采集覆盖；这是暂存区操作保护，不能替代正式CRM停止清单。CSV保留停止状态和CRM核对提示，不提供可直接群发的队列。

运行凭证为进程内随机值；请求校验Host/Origin及令牌。抓取只连已解析并校验的公开IP，逐跳核对TLS、域名及robots，拒绝本机/内网地址、携带凭证的网址和任意端口。采集不使用账号、浏览器登录态、代理池或账号轮换。

本机网络在2026-10-21将域名解析为198.18.0.0/15与2001:2::/48测试地址。仅当系统答案全部位于这两段且输入不是IP字面量时，工具使用[Cloudflare公开加密DNS](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)取得该域名的真实A记录，再按同一公开IP与TLS规则连接。解析域名会交给该DNS服务；不修改系统网络，不接受一般内网答案，也不在站点拒绝后改换通道。

## 验收范围

`test_core.py`覆盖联系人误提取、采购/销售方向、采集拒绝、重定向与内网访问限制、CSV公式、域名去重、重采集保持人工状态、本机接口防护。真实企业采集记录留本地；程序检查通过不证明采购意向、送达率或成交效果。

2026-10-21首轮验收：25项程序检查通过；真实6家企业中3家取得公开网页及合计4个联系入口，另3家遇到连接故障或网站拒绝，未更换通道继续抓取。样本中有既有CRM研究对象，不记为新增买家。发现一例关键词匹配但有指定产地/工厂代理范围的企业，已加入范围核验提示并人工暂缓。界面已验证搜索路线、筛选、选择、导出以及桌面/手机布局；没有外发、没有送达或采购回复证据。首版可用于研究与核验，尚未完成独立无人值守搜索、正式CRM自动查重及外发接入。
