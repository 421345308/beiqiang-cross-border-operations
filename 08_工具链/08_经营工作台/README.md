## 打开与使用

双击[启动工作台.cmd](启动工作台.cmd)，打开 http://127.0.0.1:8765 。启动器核对应用身份和项目目录，已有同一服务时直接打开；无须安装额外Python包。

1. 在“经营总览”选择原业务任务，查看原项目及成果。
2. 点“推进任务”，说明本次需要分析或修改什么，再点“启动 Sol”。
3. 在“实际运行”查看真实事件、结果和修改前后对照；需要调整时“继续完善”，也可暂停。
4. 审阅后点“采纳并回写”，仅将提案的精确变更写入该任务原文档。原文已被其他对话修改时停止回写，取得新提案后再审。
5. 关闭页面再打开可继续查看运行记录；后台服务仍运行。服务重启后保留记录，未结束执行显示中断，不伪装继续运行。

## 当前接入范围

- 读取三份原业务源的工作台任务、当前目标和阶段；资料更新后刷新读取，不保存第二份业务状态。
- 本机Codex CLI使用现有登录、固定 `gpt-6.1-sol`，真实生成本地资料修订提案。
- 第一版模型输入是选中任务的原业务文件和用户要求。它不自动读完整项目，不联网查买家，不调用桌面Gmail或平台连接器；外部实际操作继续由现有会话和业务通路执行。
- 明确引用的本地文档可在页面查看，包括受控客户记录；运行数据库、请求与提案只留本机，不推送公共仓库。
- 同一业务文件不能同时执行两个任务；不同文件最多两个。继续完善沿已保存CLI会话；没有可恢复会话时新建执行。
- 业务任务“已发送/待审核”等状态来自原文档；Agent执行“运行中/待审/已采纳”等状态来自本服务。采纳分析结果不表示发信或平台发布。

## 文件与运行

`server.py` 为标准库HTTP服务与运行管理；`web/` 为应用界面；`.local/runs.sqlite3` 为运行记录，`.local/` 整体不入Git。主业务源仍由[原生成器](../06_工作区维护/build_b2b_workbench.py)列出，旧HTML保留作快照。

需要Python 3.10+和已登录的Codex CLI。服务只监听本机 `127.0.0.1:8765`，未添加开机自启或计划任务。正常关闭浏览器不会停止后台服务；电脑重启后双击入口重新启动。

验证命令：`python -X utf8 tests_backend.py`；`node --check web/app.js`。业务原件、成果、记录随对象回原业务源；本入口只维护应用能力和使用方法。
