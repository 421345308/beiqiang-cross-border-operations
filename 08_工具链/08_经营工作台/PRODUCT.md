# 贝强个人工作台：产品方向

更新：2026-10-31。负责人否定了“按接口逐个加页面”的产品路线。本页替代此前架构长文；只保留当前产品判断、取舍和下一次交付。实际可用能力见[README](README.md)。

## 要解决的问题

让负责人和Agent在一个本地工作空间里，找到正在做的项目、复用已有资料、直接推进工作，并把成果留在原项目。用户不再搬文件路径、重讲背景、找上次成片或在几个工具之间复制结果。

工作台的核心是**项目、资料、工作和成果之间的关系**。画布是其中一种工作视图；LibTV、国际站API、剪辑器是可调用的能力，不能反过来决定整个产品的菜单。

当前版本只算技术试验，不能因接口可用或测试通过就算产品成立。主要问题是：没有统一项目入口；画布与Agent上下文分离；素材靠手填路径；按数组顺序画线没有业务含义；接口按钮和验收说明挤占制作空间。停止沿这套界面继续扩展。

## 参考什么，具体学什么

2026-10-31核对官方产品介绍、文档及本地代码。以下是产品设计参考，未声称逐一购买或完整试用，也未把第三方的宣传当作我们的能力。

| 参考 | 值得借鉴 | 本项目取舍 |
| --- | --- | --- |
| [Milanote影视制作](https://milanote.com/inspiration/filmmakers) | 在同一项目里组织简报、视觉参考、分镜和镜头安排 | 学项目组织与画面优先的交互，不把一排文本卡当制作工作区 |
| [Eagle](https://eagle.cool/)、[本地API](https://developer.eagle.cool/web-api) | 素材检索、预览、复用；外部程序可操作同一资料库 | 学素材选择与Agent共享数据的方式。现有文件先原位索引，不要求购买或全部迁入Eagle |
| [FLORA画布](https://docs.flora.ai/editor/canvas)、[FAUNA](https://docs.flora.ai/editor/fauna) | 选择画布对象即可给Agent上下文，Agent修改同一画布，项目内保留会话 | 这是创作协作的主要参考。先解决选中素材→交给Agent→结果回原位置，而不是给聊天换个外壳 |
| [AFFiNE](https://affine.pro/blog/getting-started-with-affine) | 文档和画布可以表达同一份内容 | 学同一资料的多视图；不立即把现有本地项目迁进另一套知识库 |
| [React Flow](https://reactflow.dev/) | 成熟的拖动、缩放、选择和连线组件，MIT开源 | 新画布优先用它替换手写交互；它只是界面组件，不是素材库、执行器或完成的产品 |
| [JSON Canvas](https://jsoncanvas.org/spec/1.0/) | 文本、文件、链接和分组的公开画布格式 | 参考/支持可读可导出的布局；生成步骤、镜头顺序和版本关系另按明确语义表达，不假称该格式能执行工作流 |
| [OpenCut当前上游](https://github.com/OpenCut-app/OpenCut) | 完整剪辑器的项目、素材和时间线体验 | 剪辑能力优先接成熟工具，不自建时间线。现有本地opencut-classic自述Legacy且用浏览器存储，不能直接当Agent共用主库 |

我的选型判断：采用**轻量本地项目服务 + 成熟画布组件 + 专业工具连接**。不把AFFiNE、Eagle、OpenCut分别再造一遍，也不将所有业务塞进某个创作SaaS。保留现有Python/SQLite和已接工具，投入集中在项目组织和真实使用流程。

## 用户怎样使用

主导航收敛为“项目、素材、工作”，连接和运行详情放设置。首页回答“继续做什么、有什么新成果、哪里需要我决定”。长期经营方向在总控里维护，不在每一页反复占据大块空间。

进入一个项目后：左侧是该项目资料与素材，中间是当前工作，右侧是Agent。当前工作按业务选择合适视图：视频用参考板/分镜/作品，商品用列表与详情，客户用往来与下一动作。切视图不丢项目上下文，不要求再次选工具账号或复制ID。

视频项目的主流程：
1. 打开一个已有项目，直接看到项目说明、参考素材、镜头与现有作品。
2. 搜索或拖入素材，点选预览，加入参考板或镜头；常规使用不填路径。
3. 选中素材或镜头，说“整理成三个镜头方案”“替换第二镜头参考”“比较这两个版本”。
4. Agent在同一项目中添加或修改结果。用户能直接看差异、播放、评论、选择版本和撤销普通编辑。
5. 需要生成或剪辑时由连接器调用现有工具，任务进度和成果回到该项目；下次继续原位置。

画布连线必须有含义：素材用于哪个镜头、哪个生成结果来自哪个输入。镜头顺序用明确的分镜排序表示。取消现在自动把所有卡片串起来的装饰线。

## 人和Agent共用什么

- **项目**：复用已有项目目录、PROJECT.md或原业务入口；记录关联对象，不按每次聊天重复建项目。
- **素材与成果**：引用原本地文件及现有产品素材索引，提供搜索、缩略图、预览、版本和被哪些项目使用的信息。检索索引可重建，原件不为界面重复复制。
- **画布/镜头/修改**：界面和Agent调用同一项目服务。Agent能列项目、读取当前上下文、搜索素材、添加/移动对象、提交结果；不能只在聊天里报“做好了”。CLI/MCP是这层服务的入口，不另维护一份状态。
- **任务**：归属具体项目，显示当前正在做什么和结果在哪里；同一项目可开不同会话。工具运行日志折叠，普通用户不需要理解执行ID。

已有Markdown/商品JSON继续承担其业务事实；SQLite承担索引、会话、运行和工作区状态。迁移一个对象时替换旧写入口，不长久双写两份事实。界面和Agent看到相同版本，本地日常编辑直接保存并可撤销。

## 具体减掉什么

| 停止/替换 | 保留与用途 |
| --- | --- |
| 停止手工卡片画布扩建、装饰连线、手填路径主流程 | 现有草稿可读；媒体读取底座复用到素材选择器 |
| 取消接口名/工作区ID/回读按钮作为主要工作入口 | 已验证连接器留在内部，项目动作自动带上下文 |
| 停止为每个按钮加新的审批状态、兜底层和逐轮验收报告 | 普通编辑直接执行；付费、真实发布/外发在发生时按现有授权处理 |
| 删除架构长文里的重复愿景、过时云部署主推荐与流水账 | 当前产品方案、运行入口、代码职责各维护一次；历史变更交Git |
| 暂停继续扩标题字段、更多查询页和服务器认证流程 | 既有国际站/网站服务继续可用，当前投入转到项目与素材及Agent闭环 |

不把“减少防御”变成批量删除原始资料。原件是生产输入；该删的是无用流程、重复抽象和失去目的的界面。

## 重构顺序与验收

长期：项目、素材、Agent、工具和业务成果在一个工作台里接续。先验证通用项目能力，再把国际站、网站、客户与国内业务接到相同入口；不按渠道再造多个工作台。

下一次开发只交付一条完整流程：**打开已有视频项目→看见真实资料与作品→选择素材→让Agent整理分镜→在同一项目看到修改并继续编辑。** 用一个真实项目完成，不拿空白画布、假数据或测试数量替代。

执行顺序：
1. 先统一项目与素材访问，做可用的项目页和素材选择器；接原项目，不要求用户重新录入。
2. 使用成熟组件替换旧画布，完成选择、拖放、分组、缩放、普通编辑撤销；同一接口供Agent修改。
3. 让Agent在项目内完成一次有价值的真实操作，结果立刻可见；LibTV负责其擅长的生成/远端创作。
4. 再补作品版本比较、生成进度、剪辑交接和其他业务视图。

交付时看：是否能立即找到已有工作、是否少了复制和重讲背景、Agent结果是否直接可用、关闭后是否能继续。主办负责产品取舍与实际体验，子Agent按清楚的独立模块实现；不再以接口数、代码量或测试数汇报产品价值。
