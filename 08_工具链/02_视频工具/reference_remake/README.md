# 参考视频 → 自己商品的整片生成

这是整片输入准备、平台接线及Hypit原生执行接入，不是剪辑器或理解模型。当前验证契约为 Hypit0.1.8 / LibTV CLI1.1.3 / Seedance2.5 / 全能参考 `mixed2video`。先把完整动态参考和真实商品图接到同一次请求，成片目标完整使用；不预先设计大量废弃生成段。是否需要分段取决于参考长度、完整动作边界和实际入口限制，不能用“一定不用剪”保证模型质量。

**当前接入：** [原生LibTV Provider](provider-libtv/README.md)已实现并在真实素材Source/Run中通过加载、端点选择与不付费计划检查。它接收Hypit模型请求、只经官方CLI执行、将结果写回Hypit资源与模型结果类型；持久记录阻止故障后的重复付费。2026-10-20已在ZX9507 R02完成获782积分单条授权的真实生成/下载/Build闭环，1个结果、无自动重试；模拟测试仍不当成片。本款详细质量与BGM试听状态见对应项目。每个新任务的草稿缓存与最新报价继续单独核对。

## 当前工作流

1. **选参考与用途。** 收集适合产品的卖货表现，不只看标签/点赞。写清希望借鉴的是观察面、动作、镜头关系还是话术；抬跟、转脚可以给出鞋口、侧线、后跟和上脚形态信息，重复不自动无效。
2. **保留原视频。** video-use负责按作品ID获取并核原件。Hypit `media probe/tile/frames`支持技术检查、疑点定位。完整音视频送生成模型；抽帧用于我们检查，不取代其动态输入。真正听审与抽帧检查分别记录。
3. **匹配自己的产品。** 优先原始商品照片。全形图锁轮廓、织纹、鞋底；第二张补上脚比例、鞋口与后跟；若参考要求完整鞋底而图没有，就补真实图或改变该展示，不让模型猜。生成场景图是有构图缺口才做，不自动付费再造每个起点图。
4. **最小差异指令。** 原视频的动态关系已经存在，避免用错误长篇拉片文字覆盖。明确视频/各张图职责；原参考里的品牌、性能、口播和音乐不自动成为自己的商品事实或成片内容。需要新脚本/声画关系的参考再用Hypit语义编排。
5. **准备与接线。** `prepare.py`校验源视频音轨、时钟、全部hash、真实同款图绑定与整片参数。`Stage-LibTV.ps1`用官方CLI上传图、移除草稿中的占位参考、绑定准确提示词，回读验收。两者均不触发生成。`Initialize-NativeProvider.ps1`创建本项目的Source/Run/Profile，`Check-NativeProvider.ps1`核图与实际端点绑定；生成仍由明确选中的Runtime Provider执行。
6. **看最终报价后提交一次。** CLI的schema没有数值价格，实际页面报价单独核对；不把示例、旧价格、划线价或720P换算成未经核实人民币。当前准备工具不调用付费生成。
7. **审完整结果。** 从头到尾播放带声音、看无声画面、单独听声音。比较鞋款身份、双腿/双鞋、接触、观察面、原动作关系、节奏、首尾和品牌落款。模型文字评价是辅助证据。正常精修可以做，但不能靠删掉大部分素材掩盖任务失败；记录缺陷区间与原因，再决定更换输入、定向编辑或重生成。
8. **复用和扩展。** 保存已接受输出与原始任务绑定。变体只改需要改变的商品/文案/配色/呈现，保留适用的已生成素材。Hypit原生Provider已接入并通过不付费检查；同一次提交的失败下载续收不重新生成，未知提交禁止自动重试。创作变体的已接受素材在Run中显式复用，不能以端点可用代替动作与审美验收。

## 调用

`prepare.py --package <适配JSON> --root <项目根> --ffprobe <已安装ffprobe> --out <本项目prepared.json>`

适配包沿用项目自身入口，至少包括 `product_id`、完整 `reference_video` path/hash/duration、同SKU `reference_images` path/hash/binding/status、prompt path/hash、model/provider/task、输出参数及 `libtv` 的 project_uuid/draft_node_id/reference_video_node_id。商品图的“已看过同款”状态只能在真正核图后写入，校验器本身不作视觉判断。输入长度超过本工具当前30秒范围会报错，不静默剪原片。

**新参考的本地准备：** 尚未上传的新候选使用 `libtv: null`，仍能核完整音视频、商品图、提示词及输出参数，结果明确为 `unbound_local_preparation`。不借用上一条参考的节点编号凑通过；接线与Runtime初始化会在任何平台操作前拒绝这个包。每条候选先核作品ID、详情页标题和本地画面是否同源，再决定商品部位能否迁移。搜索页可能自动续播别的作品，当前播放器有视频不等于所选作品已获取。声音存在和语义听审分别记录。

随后执行 `Stage-LibTV.ps1 -Prepared <prepared.json> -EvidenceDirectory <本项目执行证据目录>`。输出包含真实上传回执、绑定后的提示词、草稿回读、stage-state；复用匹配hash的上传回执。API失败或状态不明时停在该处，不能自动重试；丢失回执先查节点，不能因本地文件不存在就重复上传。平台状态及商品内容变化后重做准备和回读。

2026-10-12实测：完整28.467秒带声输入和两张不同真实商品图通过校验；五类错误输入被拒绝。两图真实上传成功，未运行草稿的当前imageList/videoList、mixedListOrder、提示词和输出参数均已回读。CLI中节点编号引用必须用不带引号的 `{{Node UUID}}`，基础参数用 `-s duration=28` 等由schema路由，不用 `settings.duration` 作为键。

**执行前的实际草稿检查：** CLI 1.1.3媒体缓存由正常连线重算，不允许直接写mixedList。类型列表、实际派生顺序、存在的缓存、提示词和参数须一致；不一致就正常刷新与回读，不能为通过测试伪造状态。17秒样本曾通过准备和原生Provider回读，但其桌面展示创意随后被负责人否决、草稿及执行目录已删除；旧28秒草稿也已删除。旧样本当时停在审核与费用确认前；10-20 ZX9507 R02已完成获782积分单条授权的真实完整闭环，不能用旧样本代替本条输入与验收。

连接诊断发现进程原代理与系统现用代理不一致，直连有间歇超时。仅在子进程使用已存在的系统代理并启用Node环境代理后，连续CLI回读恢复。未改系统设置、关闭TLS或扩大权限；不要将本机代理地址写成跨机器默认。

该工具不下载模型、不运行本地推理、不安装剪辑器、不启动后台服务。结果留当前项目；凭证、上传URL、账号草稿记录与媒体不进入公共工具仓库。
