# MiniMax H3 本地生成指南与技术事实

更新日期：2026-08-24

## 1. 核心结论

MiniMax H3 不是“首尾帧加一段自然语言就能稳定出片”的普通图生视频模型。结果会同时受到任务模式、参考素材路由、官方提示词结构、有效帧数、模型权重、Turbo LoRA、采样器、分辨率、显存预算和逐帧审核影响。

官方开源版包含 FL2VA 与 Ref2VA 两套不同扩散权重。混用会让参考输入进入错误模型路径或直接运行失败；按任务模式匹配权重和 LoRA 是技术兼容事实。复杂人物动作、身份一致性、动作模仿和镜头模仿通常更适合 Ref2VA；只有首帧或首尾帧约束时，I2VA、FL2VA 或 L2VA 往往更简洁。

本文只放两类内容：官方/运行验证过的技术事实，以及能帮助选择方案的通用引导。单个项目的题材、美术、人物、镜头和失败历史留在项目档案；尚未跨项目验证的经验留在 `07_知识库与Skills/04_AI视频知识体系/ai-video-learning-system/references/experience-ledger.md`，不会自动变成 H3 约束。

### 1.1 官方能力边界

- 单次输出时长为 4–15 秒，固定 24 fps。完整长片通常由多个独立镜头剪辑而成；若把两次生成伪装成同一连续动作，隐藏时序状态不一致会提高接缝可见概率。
- 官方支持 21:9、16:9、4:3、1:1、3:4、9:16 等画幅。开放权重 H3-Base 的原生生产基线为短边 768；宽高取 32 的倍数。
- H3 在一次生成中联合输出画面与原生 32 kHz 立体声音频，可在提示词中同时规划对白、动作声、环境声和非画内音乐；发布成片可在后期统一重采样为 48 kHz。
- 官方最高 2K 依赖 H3-Regenerate-2K：它会结合 768p 结果与原始上下文重新生成细节，不等于普通超分。该再生成模块当前未完整开源；本地普通放大只改善输出尺寸，不能恢复与官方再生成相同的语义细节。
- Ref2VA 最多接收 9 张图片、3 段视频、3 段音频，总文件数不超过 12；每段参考视频/音频为 2–15 秒，同类总时长不超过 15 秒。音频不能作为唯一参考输入。
- H3 的优势是 4–10 秒内一个清楚、连续、音画同步的事件。多人高速舞蹈、打斗、精密手部接触和远景小脸需要更多参考与验证，因为它并非逐关节动作捕捉、物理仿真或无限长视频系统。

### 1.2 最适合与不适合的任务

优先使用 H3：单人或少量人物的明确动作、人物/产品短镜头、电影化运镜、古画与照片活化、风格化动画、原生对白与音效、利用连续参考视频模仿动作或相机轨迹。

当任务依赖逐关节控制、复杂机械物理、多人队形或远景人脸识别时，H3 的生成式近似可能偏离精确目标。远景脸糊首先是主体像素预算问题；人脸承担叙事时，调整构图或使用经过验证的再生成链路通常比锐化、补帧或大幅数字变焦更有效。

## 2. 模式选择

| 模式 | 输入 | 适用场景 | 何时换模式通常更稳 |
| --- | --- | --- | --- |
| T2VA | 文本 | 无参考素材的概念镜头、风景、简单叙事 | 强身份一致性 |
| I2VA | 首帧 | 从确定构图自然发展 | 目标需要精确抵达指定尾帧 |
| FL2VA | 首帧 + 尾帧 | 单镜头、可解释的连续状态变化 | 多人物复杂打斗、仅靠额外身份图锁脸 |
| L2VA | 尾帧 | 反推合理开场并收束到指定画面 | 开场构图需要严格固定 |
| Ref2VA | 图片/视频/音频参考 | 锁身份、风格、动作、镜头、声音 | 仅想做简单首尾帧插值 |

选择提示：

1. 先判断“中间动作是否能由首尾两帧自然推断”。推断空间越大，连续参考视频与 Ref2VA 的价值越高。
2. 参考视频用于动作和运镜；身份图片用于人物、服装、体型和场景。
3. 分镜拼图只提供离散姿态；它缺少速度、受力和遮挡过程，因此不能提供与连续动作视频相同的时序信息。
4. FL2VA 的额外槽位不等于 Ref2VA 身份参考。运行日志显示素材进入正确模式，才说明参考真正生效。

## 3. 官方提示词结构

### 3.1 T2VA / I2VA / FL2VA / L2VA

首尾帧模式的第一行必须声明图片与目标视频时间点的对应关系。其后空一行，并按固定顺序书写三个字段：

```text
How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot 1) aligns with the 5.17-second mark of the target video.

integrated_multimodal_description: [Shot 1] ...

overall_soundscape: ...

non_diegetic_music: ...
```

要求：

- 提示词主体使用英文；对白、歌词和画面内文字保留原语言。
- FL2VA 通常写成一个连续镜头，描述从首帧到尾帧的可见运动路径。
- 先写整体影像媒介与初始构图，再写主体、环境、动作因果、镜头和同步声音。
- 可见的动作因果通常比抽象形容词或通用负面词列表更容易被模型执行。
- 对动作写“接触点、发力方向、重心变化、反作用、落脚和稳定过程”，而不是只写动作名称。

### 3.2 Ref2VA

Ref2VA 必须按以下六段排序：

```text
subject_definitions: ...

summary: ...

retention_analysis: ...

detailed_description: ...

overall_soundscape: ...

non_diegetic_music: ...
```

要求：

- 标签必须统一使用 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>`。
- 明确每个参考的职责：身份、服装、体型、环境、动作节奏、镜头轨迹或声音。
- 最多 9 张图片、3 个视频、3 个音频，总文件数最多 12。
- `ref_image_size=match` 更省显存；`max` 保留更高参考图分辨率、身份更稳，但每个采样步都增加参考 token 与显存开销。

## 4. 时长与帧数

H3 以 24 fps 输出，合法帧数满足 `17k + 5`。官方模板把秒数转换为帧数的公式是：

```text
max(5, round(seconds * 24)) + (5 - (max(5, round(seconds * 24)) % 17)) % 17
```

常用对应关系：

| 请求时长 | 合法帧数 | 实际时长 |
| --- | ---: | ---: |
| 4 秒 | 107 | 4.46 秒 |
| 5 秒 | 124 | 5.17 秒 |
| 8 秒 | 192 | 8.00 秒 |
| 10 秒 | 243 | 10.12 秒 |
| 15 秒 | 362 | 15.08 秒 |

提示词中的尾帧对齐时间使用实际时长并保留两位小数；例如 124 帧对应 5.17 秒。写成 5.00 秒会让模型的时间约束和真实 latent 长度不一致。

## 5. 模型与 LoRA 配对

### 5.1 FL2VA / T2VA / I2VA / L2VA

- 扩散模型：`minimax_h3_fl2va_pruned_int8_convrot.safetensors`
- 高质量加速：`minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`
- 快速预览：`minimax_h3_fl2v_turbo_4step_v1.0_768p_comfyui_bf16.safetensors`
- 8-step LoRA 对应 8 个采样步；4-step LoRA 对应 4 个采样步。
- 官方模板的 LoRA strength 为 `1.0`。降低 4-step LoRA 权重不会把它转换成高质量模式，反而可能削弱加速轨迹与基模的配合。

### 5.2 Ref2VA

- 扩散模型：`minimax_h3_ref2va_pruned_int8_convrot.safetensors`
- 加速 LoRA：`minimax_h3_ref2v_turbo_4step_v0.1_comfyui_bf16.safetensors`
- Turbo 模式使用 4 步、strength `1.0`。
- 不使用 Turbo 时，官方参考工作流为 20 步。

## 6. 采样、分辨率与显存

- 采样器：`res_multistep`。
- FL2VA 常用 scheduler：`simple`。
- Ref2VA 的官方模板默认使用 `simple`。4-step Turbo LoRA 从 `simple` 开始更接近官方基线；20-step 的 scheduler 经验直接套到 4-step Turbo 时，可能出现过曝、轮廓撕裂和纹理崩坏，适合用同一组素材做 A/B 后再决定。
- 原生短边为 768，16:9 画布常用 `1344 × 768`，宽高必须是 32 的倍数。
- H3 是 33B dense transformer；当前开源版使用 full attention，训练时使用的 sparse attention 尚未开放。
- 单卡 5090 在 1344 × 768、长时长、Ref2VA 高分辨率参考下可能 OOM。先做 5.17 秒或更低像素的动作验证，再在同一工作流上提升到最终规格。
- Sage Attention 可明显加速且通常损失很小。使用 `Patch Sage Attention KJ` 或以 `--use-sage-attention` 启动 ComfyUI；保持 fp16/bf16。

## 7. 推荐生产路径

1. **定义单一目标**：一个镜头只解决一个主要动作或一个明确的情绪变化。
2. **选模式**：首尾状态可推断用 FL2VA；身份、动作、镜头均需锁定用 Ref2VA。
3. **准备参考素材**：身份图干净明确；连续视频才能提供完整的动作速度、遮挡和受力信息；首尾帧保持人物比例、轴线、光线和背景一致。
4. **计算实际时长**：先确定合法帧数，再写提示词时间。
5. **按官方结构写 Prompt**：官方字段能把镜头、声音和时间关系显式传给模型；自由文本分镜可先整理后再进入该结构。
6. **预览验证**：固定 seed，检查动作方向、角色数量、身份、轴线和关键接触点。
7. **质量升级**：FL2VA 复杂动作可从 4-step 切到匹配的 8-step LoRA；降低 LoRA strength不是等价的质量升级。
8. **逐帧审核**：每 6–12 帧抽样，额外检查首尾、动作接触前后、遮挡和快速运动区。
9. **只返工根因**：动作不对先修参考与提示词；身份不稳改 Ref2VA 和参考图；糊帧再改运镜速度、分辨率或采样配置。
10. **实例管理（强制成本规则）**：GPU 实例只在已提交/正在执行 H3 任务，或任务刚结束后的必要下载与校验期间保持开机。生成文件已下载并完成校验后，必须立即关闭 GPU 实例；本地审核、提示词编写、素材整理、拼接与文档更新均不得占用开机实例。再次需要生成时，先检查实例状态再启动，避免空转计费。

### 7.1 画布与工作流分层

1. **ComfyUI 是 H3 的模型级生产画布**：负责参考素材、模式、权重、LoRA、seed、帧数、分辨率、采样、视频/音频 VAE 与输出。为避免历史节点图悄然改变参数，本工作区以 `官方工作流/` 下的 T2V、I2V 和 R2V JSON 作为中央起点。
2. **LibTV 是上层内容编排画布**：负责工作区、脚本、分镜、图片、视频、音频、分组、生成节点与剪辑节点的串联。模型目录会变化，创建画布前查询 `libtv model search` 和完整 schema 能避免把海螺等其他 MiniMax 模型误认成 H3。
3. **MiniMax Hub Canvas 是官方在线编排环境**：可使用官方风格化视频 Skills 和 Hub 节点。Hub、ComfyUI 与 LibTV 的节点接口不同，先确认当前环境再复用流程。
4. 当前推荐总流程为：选题/脚本/分镜 → 静帧锚点 → 中央提示词校验 → ComfyUI/CompShare 生成单镜头 → 下载并关 GPU → 逐帧验收 → LibTV 或本地后期完成长片。

LibTV 的可用模型属于运行状态，不沉淀为永久知识；每次需要把 H3 放入 LibTV 画布时重新查询即可。2026-08-24 的项目检查结果已留在经验候选池，而不是作为长期模型能力写死在本指南。

## 8. 审核清单

- [ ] 输出帧数符合 `17k + 5`。
- [ ] 提示词尾帧时间等于实际帧数除以 24。
- [ ] 模式、扩散权重和 LoRA 属于同一系列。
- [ ] LoRA 名称、步数和 strength 正确配对。
- [ ] 参考素材在运行日志中确实被模型读取。
- [ ] 人物数量、身份、服装、体型和屏幕方向稳定。
- [ ] 动作由上一动作的力和重心自然触发，无停顿、倒退或滑步。
- [ ] 手脚接触、遮挡、落地、毛发和衣物次级运动合理。
- [ ] 运镜有动机，不以过快平移掩盖模型错误。
- [ ] 快速运动区无糊化、重复肢体、缩短身体或跳帧。
- [ ] 音效、环境声和画面动作同步。
- [ ] 最终画幅符合发布平台，不靠后期裁切牺牲主体。

## 9. 经验如何进入本指南

项目中的异常先进入外部经验候选池，用“条件—机制—后果—倾向性建议—范围—证据”记录。只有跨项目重复或通过清楚对照验证的结论才进入本指南；进入后保留能改变选择的抽象结论，不携带项目人物、题材、旧文件名或长负面词表。

兼容性事实不需要等待多项目复现，例如帧数网格、模式与权重、LoRA与步数、官方字段结构。这些事实由官方资料和运行校验维护。创作性经验则保留弹性，说明什么做法可能带来什么结果，而不把一种成功路径写成唯一答案。
