# 贝强 MiniMax H3 透明生产母版 V1

## 这套母版解决什么

中央官方 ComfyUI JSON 继续负责正确的节点连接；本母版为每个候选建立可见、可编辑、可复现的生成包。用户不必等视频生成后才看到 Prompt 和参数。

每个候选会产生：

```text
项目目录/generation/
├─ prompts/<candidate>.txt                 完整可编辑 Prompt
├─ manifests/<candidate>.json              参数、素材职责和版本关系
├─ workflows/review/<candidate>.canvas.json 可在 ComfyUI 打开的审阅画布
├─ workflows/resolved/<candidate>.api.json  实际提交节点图，ready 前必须存在
└─ outputs/candidates/<candidate>.mp4       候选输出
```

## 中央画布映射

| 模式 | 中央可视化画布 |
|---|---|
| T2VA | `官方工作流/video_minimax_h3_t2v.json` |
| I2VA / FL2VA / L2VA | `官方工作流/video_minimax_h3_i2v.json` |
| Ref2VA | `官方工作流/video_minimax_h3_r2v.json` |

审阅画布是中央画布在某个候选建立时的快照，用于查看节点和讨论参数。中央画布仍是节点兼容关系的唯一权威来源。审阅画布有改动时必须更新运行清单哈希；真正提交前还要保存解析后的 API JSON，避免“看到的画布”和“实际跑的图”不同。

## 新建候选

```powershell
& .\New-H3GenerationPackage.ps1 `
  -ProjectRoot '项目绝对路径' `
  -ShotId S01 `
  -CandidateId S01_v01 `
  -Mode Ref2VA `
  -Width 1024 `
  -Height 768 `
  -Frames 124 `
  -Seed 123456
```

工具会创建结构合法的官方 Prompt 骨架，复制对应中央画布供审阅，计算哈希并建立 `draft` 运行清单。它不会启动 ComfyUI、GPU 或提交任务。

## 提交前状态

1. 用户检查并修改完整 Prompt。
2. 在 Manifest 中登记参考素材、标签和职责。
3. 确认可见参数与本轮单一变化。
4. 执行 `Update-H3GenerationPackageHashes.ps1`，校验修改后的 Prompt/画布并同步哈希。
5. 由中央执行器生成本次 `resolved/*.api.json`，再执行一次哈希同步。
6. 运行 `Test-H3GenerationPackage.ps1 -RequireReady`。
7. 只有校验通过且状态为 `ready` 才能启动 GPU 和提交。

## V1 边界

- V1 已实现生成包、Prompt 骨架、画布快照、哈希和离线校验。
- 同一 CandidateId 不允许覆盖；修改方向形成新候选，普通文字修订可在原候选仍为 `draft` 时同步哈希。
- V1 不把未经验证的自定义节点加入官方 H3 核心。
- 审阅画布中的改动目前需要回写 Manifest；下一次正常启动 ComfyUI 时再验证前端 Subgraph 参数提升和从画布自动导出 API 图的兼容性。
- 人脸修复、超分、补帧和自动质检节点是否已安装尚未在关机实例上核验，因此不列为当前可用能力。
