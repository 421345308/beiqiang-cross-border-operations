# Hypit 接入评估

评估日期：2026-09-15  
评估对象：Hypit `0.1.8`（仓库当前 `package.json`）  
当前结论：**已加入为实验性的“语义编排、批量变体与可编辑合成层”，不替换 LibTV、Seedance/H3、video-use 或现有剪辑工具。零付费本地 smoke test 已通过；下一阶段用真实本地素材验证两版复用收益，再决定是否进入常规生产。**

- 官方 Hypit Skill 已安装；项目 Distribution 固定为 `@hypit/hypit@0.1.8`。
- 已建立统一启动器、独立 Runtime Profile 和本地 FFmpeg/HyperFrames 路径。
- `check` 与 `plan` 通过；规划中的 3 个请求全部为 `local, no Provider charge`。

## 1. 它是什么

Hypit 不是新的基础视频生成模型。它是一套面向 AI Agent 的视频创作语言与运行时：

- 用 SVML 描述脚本、素材、字幕、B-roll、动效与画面关系；
- 用 Script Selection / Moment 把画面事件绑定到词义和台词，而不是手写绝对秒数；
- 用 `.svrun` 选择本次要生成的输出和可复用候选素材；
- 用 Runtime Profile 把生成需求路由到具体 Provider；
- 用本地 FFmpeg 与 HyperFrames/Chromium 完成标准化、合成和渲染；
- Build Results 保留输出、执行状态与中间证据，Studio 提供可编辑时间线和评论界面。

它的真正优势不是“生成画质更高”，而是把一次视频方案变成**可检查、可复用、可批量变体、可换模型/Provider 的生产图**。

## 2. 与贝强当前视频能力的关系

| 当前能力 | 主要职责 | Hypit 的关系 |
| --- | --- | --- |
| LibTV CLI | 通用 AI 视频的画布、素材和节点编排；当前优先入口 | 高度重叠。Hypit 不应直接取代，而应只在语义驱动、批量变体强的项目中试用 |
| Seedance 2.5 | 当前优先生成模型 | Hypit 已声明 Seedance 2.5 模型契约，但官方现成执行通道主要是 HypiHub；贝强当前既有通道不能假定直接复用 |
| MiniMax H3 / ComfyUI | 本地/云 GPU 的 H3 生成与中央规范 | Hypit 有 H3 请求契约，但未发现可直接驱动贝强现有 ComfyUI 官方工作流的内置 Provider；接入需另写 Provider，且不能绕过现有 H3 校验规范 |
| video-use | 下载、抽帧、转录、剪辑、成片视觉 QA | 互补。Hypit 可产出与合成，video-use 继续承担独立成片验收；Hypit 的 Studio 预览不能替代最终 MP4 QA |
| Remotion / HyperFrames | 程序化动态图形与渲染 | Hypit 本地渲染本身基于 HyperFrames，适合组件化字幕、榜单、卡片、播客/访谈版式；和 Remotion 有明显重叠 |
| OpenCut | 人工时间线编辑 | 互补。Hypit 适合结构化自动生产，OpenCut 仍适合人工精修和非结构化调整 |

## 3. 最适合的贝强场景

### 高适配

1. **TikTok/短视频批量变体**：同一结构替换产品、开场 Hook、语言、CTA、B-roll 和字幕样式。
2. **口播、UGC、采访、播客切片**：字幕、卡片、B-roll、排行榜或卖点揭示跟随词义自动重排。
3. **多语言本地化**：改台词后让字幕、画面揭示和 B-roll 继续跟随新的语音时间。
4. **参考视频结构复刻研究**：把镜头关系、字幕落点、动效触发和素材角色沉淀为可编辑工作流，而不是只写拆解报告。
5. **大量复用同一版式**：当第二条到第一百条只是结构内变量变化时，Hypit 的价值明显高于手工复制时间线。

### 低适配

1. 无口播、以表演和情绪连续性为主的电影感叙事；词锚定优势较弱。
2. 一次性、镜头数量很少、无需变体的单条成片；新增 DSL 和运行时不一定划算。
3. 需要人工导演判断的复杂混剪；仍应以实际观看、相邻镜头关系和音乐为准，不能把语义锚定误当自动剪辑质量。
4. 当前 H3 中央工作流已经稳定的生成任务；Hypit 不能成为绕开官方工作流、帧数校验、LoRA/模式匹配的捷径。

## 4. 当前接入阻点

### 环境

- Hypit 要求 Node.js `>=22.15.0`；系统默认 Node 为 `20.14.0`，不满足。
- Codex 捆绑运行时已有 Node `24.19.0`，可以用于隔离 POC，不必直接升级或覆盖系统 Node。
- 本地已具备 FFmpeg/FFprobe 9.0，但未加入系统 `PATH`；Hypit Runtime 需要显式配置或为 POC 临时注入路径。
- 系统当前没有可直接调用的 `uv`；只有使用本地 WhisperX/OpenCV Managed Program 时才是阻点。首轮 POC 可完全绕开。

### Provider 与现有生成通道

- 官方包把 Model 与 Provider 分离，这是好设计，但“声明支持 Seedance 2.5/H3”不等于能直接复用贝强现有 API、LibTV 节点或 ComfyUI 工作流。
- 官方现成 HypiHub Provider 会上传参考图、视频和音频，并调用其托管服务。若使用它，需单独确认账户、实时价格、数据传输与付费授权。
- 若要复用贝强当前 Volcengine Ark Seedance 或 ComfyUI H3，需要开发并验证贝强自有 Provider。这个工作应在 POC 证明 Hypit 的编排价值后再做。

### 成熟度与升级风险

- 当前版本仍为 `0.1.8`，项目很新、更新频繁，Source/Runtime/Studio 接口可能继续变化。
- 应固定 Hypit Distribution 版本和 lockfile；不要跟随 `main` 作为生产依赖。
- 先把它作为单独工具目录和独立项目依赖，不修改现有生成脚本与中央规范。

### 许可证、内容权利与隐私

- 许可证允许企业内部、自用基础设施和为客户开展工作；禁止未经书面授权的多租户托管与商业再分发，并限制移除 CLI/报告等界面中的 Hypit 名称、Logo 和版权信息。
- “爆款克隆”不是版权许可。用于参考的视频必须有合法使用权，实际输出不能复制受保护表达或冒用人物、品牌、声音。
- 使用 HypiHub 时，输入素材、URL、提示词和生成输出会被服务处理；其隐私政策称用户内容可能为提供服务而保留，并可能传输到第三方 AI 基础设施。贝强 SKU 原件、客户素材、未公开品牌资料默认不走托管通道，除非单独核准。

## 5. 推荐接入方式

### 定位

将 Hypit 定位为一个**可选生产后端**：

```text
项目 brief / 合法参考
        ↓
Hypit：语义脚本 + 组件关系 + Run/Build 复用
        ↓
已有本地素材 或 已明确选择的生成 Provider
        ↓
Hypit 本地合成与可编辑 Studio
        ↓
video-use 对最终 MP4 做独立视觉 QA
```

它不改变以下规则：

- 通用 AI 视频默认仍优先 LibTV + Seedance 2.5；
- H3 仍先走中央 Prompt、官方工作流和校验器；
- 任何扣点、托管模型调用或云 GPU 运行仍需当次明确授权；
- 贝强商品视频仍需 SKU 原件与对外事实证据；
- 参考结构复刻仍需版权、肖像、声音和平台政策审查。

### 三阶段试点

#### P0：零付费本地 POC（推荐下一步）

- 固定 Hypit `0.1.8`，在 `99_临时区/Hypit_POC/` 建隔离项目；不要全局接管现有视频 Skill。
- 使用已有、已授权的本地短视频素材，不登录 HypiHub，不调用任何生成模型。
- 只验证：SVML/SVS、词锚定字幕、B-roll/卡片触发、`check`、`plan`、本地 HyperFrames 合成、Build Results、Studio 可编辑性。
- 做两个版本：只改一句台词/一个卖点，检查字幕与画面事件是否能自动跟随重新排布。

通过标准：

- 两个版本都能重跑并得到可定位的构建记录；
- 不手改绝对时间码即可完成主要字幕/B-roll/动效同步；
- 成片通过 video-use 视觉 QA；
- 相比现有方式，第二版的制作和排错工作明显减少；
- 项目文件没有凭证、上传缓存和大媒体进入 Git。

#### P1：接一个非敏感生成通道

- 先选择 HypiHub 或贝强自有 Provider 二者之一，不同时扩张。
- 提交前用 `hypit pricing <run>` 获取当前报价，并按贝强付费生成规则确认模型、时长、分辨率、数量和预算。
- 只用非敏感测试素材验证 Seedance 2.5 一条链路；不要同时接 H3、声音克隆和批量 100 条。

#### P2：决定是否建设自有 Provider

只有 P0/P1 证明语义复用价值后，再评估：

- Volcengine Ark Seedance Provider；
- 贝强 ComfyUI H3 Provider（必须调用中央生成包和校验，不复制历史工作流）；
- 与 LibTV 的职责边界：LibTV 继续做自由画布，Hypit 只做结构化、可批量复用的语义模板。

## 6. 最终判断

**值得试，但不值得现在就“全面加入”。**

最有价值的不是其宣传中的“克隆爆款”，而是三点：

1. 词义驱动的字幕、B-roll 和动效关系；
2. 可显式复用生成结果的 Run/Build；
3. 同一结构的大规模变体生产。

对贝强而言，优先验证 TikTok/UGC/口播模板，而不是电影感长叙事，也不要先做深度 Provider 开发。若零付费 POC 不能证明“第二条视频明显更省”，则保留研究记录、不进入生产栈。
