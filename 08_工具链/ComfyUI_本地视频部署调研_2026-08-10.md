# ComfyUI 本地视频部署调研

日期：2026-08-10

## 现有设备

### Windows 笔记本

- CPU：AMD Ryzen 9 7945HX，16 核 32 线程
- GPU：NVIDIA RTX 4060 Laptop，8GB VRAM
- 内存：32GB
- 推荐模型盘：`E:`，可用空间约 1.1TB

### Mac

- 已知：Apple M4，48GB 统一内存
- 待确认：M4 / M4 Pro / M4 Max、GPU 核心数、macOS 版本、可用磁盘空间

## 结论

不建议把全部希望押在 Mac 版 ComfyUI。Apple Silicon 能通过 MPS 运行 ComfyUI，但大型视频模型仍存在 FP8、算子兼容、条纹、VAE 解码和速度问题。

更合理的是双机分工：

1. Windows 使用 ComfyUI 跑 CUDA 兼容性更好的轻量视频模型。
2. Mac 使用官方 LTX Desktop 2.3 做本地高质量 I2V 对照测试。
3. 高质量静帧先定稿，再将每个镜头生成 3-5 秒，而不是直接生成完整 15 秒。
4. 最后统一做插帧、放大、剪辑和音乐。

## 推荐模型

### 1. Wan2.2 TI2V 5B

- 平台：Windows ComfyUI
- 用途：最终 I2V、建筑微动、云海与水流
- 优势：ComfyUI 官方文档明确说明 5B 版本可通过原生卸载适配 8GB VRAM。
- 风险：速度不快；Apple Silicon 近期仍有垂直条纹问题，不作为 Mac 主方案。

### 2. LTX-Video 2B 0.9.8 Q8

- 平台：Windows
- 用途：低成本草稿、动作和镜头测试
- 优势：官方仓库给出的 RTX 4060 8GB 数据为 720×480×121 帧低于一分钟。
- 风险：模型代际较旧，最终质感通常不如新的 Wan 或 LTX 2.3。

### 3. LTX Desktop 2.3

- 平台：Mac M4 48GB
- 用途：高质量 I2V 对照和最终候选镜头
- 优势：官方桌面应用明确支持 Apple Silicon，启动时有至少 15GB 可用内存即可进入本地生成模式。
- 风险：22B 模型较大；MPS 速度和节点兼容性不如 CUDA；建议先关闭音频生成，仅生成视频。

### 4. FramePack

- 平台：Windows RTX 4060
- 用途：较长镜头实验
- 优势：官方称 13B 模型最低可使用 6GB VRAM。
- 风险：4060 Laptop 生成速度可能很慢；当前项目单镜头仅 3-5 秒，优先级低于 Wan2.2 和 LTX。

### 暂不推荐

- HunyuanVideo-1.5：官方要求 Linux、CUDA 和最低 14GB VRAM。
- Wan2.2 14B：当前 Windows 只有 8GB VRAM，Mac MPS 兼容性也不足以作为稳定生产方案。
- LTX 2.3 ComfyUI 完整工作流：官方文档建议 CUDA GPU 32GB+ VRAM；Mac 更适合先用官方 LTX Desktop。

## 天宫短片建议工作流

1. 先完成 5 张 16:9 高质量连续静帧。
2. 使用 Windows 的 LTX 2B 对每张图生成低分辨率 3 秒草稿。
3. 只保留运动合理的 2-3 个镜头。
4. 用 Windows Wan2.2 5B 和 Mac LTX Desktop 2.3 对同一张图做 A/B 测试。
5. 选择画面稳定、建筑不变形的模型生成最终片段。
6. 使用 RIFE/FILM 插帧至 24/30fps，减少卡顿。
7. 使用分块超分放大至 1080p，再进入 OpenCut/FFmpeg 剪辑。

## 首轮基准测试

不要下载全部模型。先测试同一张天宫图片：

- Windows LTX 2B Q8：3 秒、720×480、低步数草稿。
- Windows Wan2.2 5B：3 秒、低分辨率 I2V。
- Mac LTX Desktop 2.3：3 秒、关闭音频、I2V。

比较四项：建筑结构稳定性、云水自然度、掉帧/闪烁、单次耗时。测试通过后再决定主模型。
