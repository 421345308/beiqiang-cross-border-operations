# 电商商品与订单管理系统 V1.0

本文件是系统和抖店自研资质准备的唯一项目入口。本轮已实现并验证本地管理系统；申请主体以本地营业执照和登录后的店铺回读为准，与工作台公司不同，不假设关联关系。

负责人验收入口：本目录 `申请材料/负责人验收.html`。其中汇总7份PDF、可编辑HTML、填报信息稿、官方依据、源码校验和验收记录。企业原件、店铺字段、截图、申请材料和数据库均留本地，排除公开Git。

## 当前交付与限制

- 商品与SKU：只读型号引用、名称及价格维护、身份不可改绑、CSV整批导入导出。
- 库存与订单：有依据的库存调整、唯一订单编号、价格快照、事务预留、取消返还一次、发货凭证和操作记录。
- 维护：本机登录、首次密码设置、加盐摘要及会话退出，本地Host/Origin/CSRF校验、CSV公式转义、SQLite一致性备份、演示与正式库隔离。
- 抖店协议准备：独立模块完成UTF-8排序序列化、HMAC-SHA256签名、POST请求构造和脱敏摘要；只作离线测试，不发网络请求。没有AppKey、授权令牌或正式发布回执，尚不能自动上品。
- 软件是本机单操作员工具，已有真实登录页；没有云端服务、多角色权限、平台订单同步或线上付款。真实接入尚未完成，不能冒充已对接。
- 软著登记费停征。已准备程序和文档，尚未完成机构实名、正式申请表、签章、受理或发证；研发支出凭证仍缺。

## 启动与验证

运行程序仅使用Python 3.11及以上标准库，浏览器支持现代JavaScript即可。Windows可运行本目录的 `启动演示.ps1`，或在本目录执行：

```powershell
python -X utf8 app.py --demo
```

打开 `http://127.0.0.1:8766/`。演示库为 `.local/demo.db`，全部DEMO型号、数量和订单是功能测试数据。正式模式不加 `--demo`，默认空库 `.local/production.db`，不会复制演示数量。模式不符时拒绝启动。程序仅监听127.0.0.1；不要将端口直接暴露公网。Ctrl+C结束前台服务。

本机账号为admin；演示密码为Demo-Only-8766，仅用于DEMO库。正式库首次启动必须由负责人设置12至200字符密码，不能通过初始化入口覆盖。密码以随机盐和PBKDF2摘要存储；会话最长8小时，退出或服务重启失效。此登录与抖店账号分开，不是公网安全认证。

型号默认只读引用工作台唯一产品身份台账，不改原事实源，不推断其属于本次申请主体、真实库存或可售权利；正式使用前须按真实主体核对。可用 `--catalog` 指定包含 `products`、其中每项含 `id` 的JSON台账。不得借此创建与原事实源冲突的身份。

SKU初始库存为0，数量通过有依据的流水登记，不代替实物盘点。订单不保存顾客姓名、手机或地址。导入六列表头为 `code,model,title,color,size,price`，价格单位元且最多两位小数；导出增加 `available_stock` 供核对，重新导入前移除该列。

一致性备份（目标须为新文件）：

```powershell
python -X utf8 app.py --demo --backup .local/demo-backup.db
```

恢复前停止服务、保留现有数据库，用 `--db` 指向核验后的备份并选择相同模式。不能把演示库当正式库恢复。

```powershell
python -X utf8 -m unittest -v test_app test_adapter
python -X utf8 doudian_adapter.py
```

验收在Windows、Python 3.11.7和SQLite 3.41.2上进行，共17项，涵盖本机认证、摘要存储、事务回滚、并发不超卖、重复订单、取消、发货及价格快照、CSV、SKU身份、数量金额边界、隔离、HTTP来源、备份和离线协议。Chrome验收登录与退出、SKU创建、库存调整、预留、取消返还、CSV导入、发货凭证和日志。数据均为DEMO，无平台写入。最终通过状态、源码和文件校验见本地 `申请材料/验收记录.json`。

## 当前准入与后续顺序

2026-10-15已核对登录后的店铺主体信息和开发者认证信息：店铺、开发者和执照公司名称及信用代码一致，资质列表暂无数据，**店铺类型为企业店**。[商家后台系统规范](https://op.jinritemai.com/docs/guide-docs/1608/7924)现行条款明确“仅面向店铺类型为‘官方旗舰店’开放入驻”；当前尚不满足，也没有豁免证明。开发者账号实名不等于商家后台系统类目资质通过。

已查看升级页但未发起变更。官方旗舰店另需知名/成熟品牌、自有或一级独占授权等条件，有入口不等于可获批。应先请平台明确实际店铺的可行准入路径，再决定云资源或代理投入。不能保证本店通过，不能填写虚假类型。

软著可继续按实际软件和权属准备。负责人核对主体、开发关系、权利取得与范围、完成日期、发表状态及经办人，完成版权登记机构实名。正式表单由登记系统生成，真实签章后提交。受理日起60日内审查的规定不包括前期准备，不能承诺次日拿证。源码若公开同步，应据实际公开记录核对发表状态。

取得有效证书及平台准入后，补真实研发支出、技术联系人和团队规模，核开发者主体一致性，提交类目资质；获批再创建应用、店铺授权、联调商品接口并保存正式回读。当前软件未向抖店发送请求。

版权登记系统本轮正常Chrome访问显示403地区限制，未取得当前完整登录后表单。用户需在可正常访问的官方环境继续实名和提交。正式协议、身份验证与签章按真实当事人和当时页面办理。

## 材料与隐私

运行源程序为 `app.py`、`index.html`、`style.css`、`client.js`、`login.html`、`login.js`、`doudian_adapter.py`。鉴别材料保留全部7份源码内容（仅分页时去空白行和折行），不足60页交存全部，不复制凑页。完整原始文本和SHA256另附。

`application_content.py` 与 `build_documents.py` 是材料工具，用ReportLab和Windows宋体生成PDF；图示来自实际DEMO界面，官方模板栏目已读取。生成需 `.local/申请主体/主体信息.json` 及截图，它们不在公开代码中。`verify_materials.py` 记录测试、哈希、页面检查并渲染供视觉验收。材料环境依赖与应用运行依赖分开。

证照、店铺回读、证件、联系人、账单、数据库和申请PDF均被 `.gitignore` 排除。仅同步非敏感原创代码、通用说明及测试，不夹带其他任务改动。本地包是准备稿，不是有效证书、已盖章表单或受理证明。
