# WorkBuddy：HR执行指南

更新：2026-10-01。只读本文和当次任务指定证据；不遍读工作台。

## 当前指挥方式

- 负责人明确要求优先 CLI，停止用频繁 computer-use 点击传递 WorkBuddy 工作；也停止 Accio Work 消耗积分。
- 使用 `run_workbuddy_task.mjs TASK_FILE OUTPUT_DIR`，模型固定 `deepseek-v4.1-flash`，通过已认证 WorkBuddy 主机请求通道调用，凭证仅在内存，不读取 Accio 进程凭证。
- 输入写清事实、范围、输出路径和验收条件，分小批实际业务任务。XML/JSON整理为多行，避免工具单行截断导致循环读取。保存任务、流式会话、终态和请求状态，我方复核产物后再授权范围内执行下一步。
- CLI 与桌面原生聊天自动显示尚未验证；共享记录或 CLI 恢复成功不能算界面同步。不要为了显示逐次回到桌面点击，也不要修改数据库伪造会话。
- 2026-10-01 官方 `agent-browser@0.38.1` 已通过 `--cdp` 连接既有 Chrome；回执显示 reused=true、launched=false、relaunchedBrowser=false。可用于 API 缺失字段和公开页检查，不能把浏览器连接成功当成已登录国际站或商品验收完成。

## 任务入口

负责人已授权HR001–HR067真实鞋款替换。业务规则取唯一《国际站商品全生命周期SOP》，逐款事实取当次冻结计划和原件。本文只补充执行经验，不能提供其他鞋款的材料、尺码、价格或供应承诺。

1. 任务必须列明商品ID、字段范围、输入路径、输出路径和完成条件。只处理这些对象。
2. 一家族A/B/C对应同一真实鞋款，公开型号分别为HRxxx-A/B/C。现有历史缺失链接不得自行重建。
3. 有对应实鞋和有效采购入口可继续；后台999是可询货标记。外采不是贝强自产，不承诺实存999双。
4. 优先API；API不支持的字段及买家页视觉验收才用浏览器。正式提交是否属于本次任务须看任务范围，不能自行扩大。

## 图片与标题

- 首图要鞋型完整、清晰、有买家点击理由；逐色核对标签与实拍、官方CDN、SKU和公开选择结果。图片数量或质量分不代替视觉判断。
- 鞋型、颜色、鞋带、缝线、鞋底均以原件为准。没有真实鞋底图就不生成鞋底。生成图不能证明实物。
- 整套公司图复用负责人认可的原版v3，不重新裁切、加框或发挥；质检辅图复用已核准文件33358345636。
- 供应商名、来源平台、外采货号、031等内部来源信息不出现在买家文案或图中；内部台账保留真实对应。
- 标题讲真实品类与有证据的特点、场景；与首图一致。A/B/C保留真实搜索意图，不能只机械换词或堆关键词。不能擅写宽楦、防水、防滑、医疗功效或认证。
- 负责人2026-09-29再次纠正：本批HR标题不以颜色、EU/US尺码或内部型号占位，也不能靠换颜色区分ABC。先选有真实品类支撑的核心搜索词，再用一至两个已证实的结构/材料特色和合适用途组成自然短语。颜色与尺码放SKU、属性和图中；长短服务表达，不硬填128。最新远端1691d62/e4c6ae9为结构与流量参考，不能把BQ事实或热榜建议的New/Hot Sale/High Quality当成HR事实。
- 已实测Workctl关键词字段是单一字符串，但不能用逗号串联多个短语：HR017 submit返回`Keywords contain an illegal character: ,.`，改为自然关键词短语后成功。写草稿成功不等于最终submit可通过。
- 保留单款已确认的三档价，数量档、FAQ与公开展示一致；不从旧脚本复制新款商业字段。

## 已验证的执行办法

- 官方图片银行：上传前冻结文件SHA，保存file_id、URL和业务回执；CDN下载与批准文件核对。仅使用本店正式Alibaba CDN。
- 草稿读取覆盖完整24组件。每一步前后对比完整对象，保护未授权字段；SKU用实际ID和库存DTO，不能只按数量通过。
- 图库ADD可能追加，不能假定替换。需要替换时先按真实旧URL/分组DELETE，回读确认目标为空，再ADD目标并完整对比；未正式提交前不要让不完整草稿上线。
- 包装、SKU、公司模块等不属于当次变更时保护原值。仅允许已有证据支持的审核状态、时间、数组顺序和CDN路径等正规化。
- `success:true`且`content:[]`不能算业务成功。编辑须有正向业务回执；必要时一次只读回查，禁止自动重发写入。
- 提交后加入批次待验队列，继续下一款，统一查审核/质量/买家页，不逐款轮询等待。
- 本轮HR016实测：删除图库后的完整读取可能省略空`images`键。先核实完整对象只有这一处差异，再将已证实为空的字段按空集合比较；不能忽略其他缺字段，也不能再次删除。
- 当前正式提交CLI需要`--yes`。仅在任务已明确授权正式提交时使用；未带参数的本地校验失败不算上游提交。正向回执后不重发写入。
- 标题修改可能同步改变公开URL的标题片段。只有官方HTTPS域名、同一商品ID、与新标题一致的派生片段可记录为预期变化；不能放宽完整对象保护。

## 额度与故障边界

- 模型选择以当前实际计费或额度规则、任务合格率和返工成本共同判断；token数只记录用量，不能单独证明节省额度。未知计费不标为低成本。
- 事实提取和清单整理优先已验证的经济模型；标题策略和图片终审使用足以胜任的模型。确定性字段变更及完整比对优先直接执行脚本/API，减少模型调用。只有任务质量不合格且指导后仍未改善，或能力不支持时才升级模型；不为降价放宽商品质量验收。
- 简单证据提取、载荷整理用当前支持的文本模型及低推理档；视觉用支持图片的模型。模型ID从本机当前help核实，不根据旧记录猜。
- 新机械试点实际CLI限制8–12轮；不要在提示词写12轮、启动参数却给40轮。不复制整段旧会话，不重复下载已缓存原件。
- 本机2026-09-29曾出现缺`windows-child-process-containment.cjs`以及`Authentication required`。遇到这类错误立即保存失败与已产出文件；不要反复启动、绕过隔离、追网关或编造完成。
- 进程退出0不等于任务成功；检查最终事件、必需交付物和实际回执。PID须与程序身份/启动时间一起核实，防止PID复用误判仍在工作。
- 每次交付一个短`result.md`和可追溯数据：已完成、未完成、证据路径、修改回执、失败原因；最终图片和买家价值由Root逐张主审，正式与公开回读由Root复核。
