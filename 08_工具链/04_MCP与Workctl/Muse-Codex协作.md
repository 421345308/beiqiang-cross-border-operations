## 默认分工

按现有工作记录采用下面的分工，后续以实际交付效果调整。两者都可以研究、执行和复核；任务由更适合其资料、工具和上下文的一方主办。

| 角色 | 优先承担 | 向下一位交付什么 |
| --- | --- | --- |
| Muse | 经营问题梳理、外部调研、机会和内容方案、已有业务任务协调与进展回收 | 具体问题、来源、取舍、预期交付及对应业务文件；接收执行结果后更新经营判断 |
| Codex | 代码与数据处理、工具/API接入、网站与自动化实现、复杂问题诊断和结果验证 | 可用产物、实际验证、实现取舍及下一动作，直接写回所属项目 |
| 主办 Agent | 对本轮结果负责，按需请另一方挑战假设或检查关键结果 | 完成原任务条目，提出下一项最有价值的工作；普通小任务自行闭环 |
| 负责人 | 确定经营方向、实际供货能力、预算与关键商业取舍 | 决定写入相应目标或业务源；已有授权按原范围继续使用 |

协作围绕实际问题展开，轮次按解决问题所需决定。一次任务能独立完成就直接完成；需要合作时传递业务文件位置、本轮交付、写入范围和验收条件，避免把整个聊天历史当交接材料。

## 资料如何归位

- 有效知识、决策、任务进度直接更新本地业务文档；这里只链接相应来源。客户开发、RFQ、抖店和视频各自维护自己的任务。
- 正式CLI任务保持同一项目目录与 `CODEX_HOME`，按明确UUID串行续接。可执行文件记录实际路径和版本，升级后重新解析；正式任务不使用 `--ephemeral`，多任务不使用 `--last`。
- 原始会话由Codex保存在其会话目录。需要保留的任务答复、事件、stderr和调用元数据放所属项目受控证据目录，按任务与轮次定位；TEMP只作执行暂存。CLI输出不代替业务文档回写。
- 本次已将8份客户开发证据、9份技术证据从TEMP转存到上述本地目录并核对SHA-256；manifest记录原路径与哈希。这些目录受Git忽略，公开同步范围沿用根AGENTS。
