# 浏览器连接排障

更新：2026-10-31。主办：Codex国际站同款与优化会话。当前故障仍待完整恢复验收，不能把成功读取一次写成已修好。

## 当前症状与已验证边界

- 当前Codex桌面包：26.1027.3384.0。Chrome扩展在浏览器清单中存在，能列标签ID、标题及URL；因此不能只因页面调用失败就判扩展完全断线、国际站退出登录或用户未授权。
- 旧BQ008标签读取实际返回`Debugger unattached`；此前新标签初始化也多次在页面状态读取时超时，工具层出现过`Page.getFrameTree`超时。
- 从浏览器回退到原生Windows窗口时，工具无法可靠识别当前浏览器URL，安全停止该轮Computer Use。这是URL无法核实导致的保护，不能当成网站业务拒绝，也不能关闭检查或换隐蔽控制通道。
- 本次沿同一个Chrome连接，用文档支持的`browser.tabs.new()` → `tab.goto(精确商品URL)` → `tab.playwright.domSnapshot()`，成功读到BQ008-W1新标题、10.90/9.19/8.78数量价、亮点和原采购CTA。这说明页面与登录态在该次可正常读取，旧标签调试绑定失效是一个已观察事实；底层为何脱离尚未确定。
- 随后`tab.screenshot()`超时并重置JavaScript会话；恢复原连接后，目标标题读取再次超时。故障不是单纯“新建标签即可永久解决”。截图超时后的配色点击没有获得执行回执，不视为已点击。
- 同日经营工作台部署源也记录`Debugger unattached`及标签交互超时。可能影响多个任务；尚未证明是并发控制、扩展版本或桌面进程中的哪一项导致。

## 现行处理顺序

1. 按当前工具文档恢复原浏览器绑定，确认ID/标签/URL，不把浏览器编号当长期固定值（本机会同时列Chrome和Edge）。旧标签失效时可在原浏览器新建干净标签，先正常导航并读取正文。不能不断新开标签掩盖失败。
2. 分别验证元数据、正文、截图及一次低影响页面操作；任何一项失败都保留实际错误。单次DOM可读只算部分恢复，不能据此宣布稳定。
3. 页面调试连接持续失败时，按官方排障重启Chrome，再核扩展是否在当前配置中正常连接。当前已请负责人完整退出Chrome并重新打开/恢复标签，等待完成；没有擅自结束浏览器进程、关闭其他任务或改变权限。
4. 若重启浏览器仍失败，再按官方顺序检查桌面应用更新/重复安装、正确浏览器配置及扩展连接；必要时正常重启桌面应用。重启影响正在运行的聊天时由负责人操作。重装扩展只走应用内正式设置流程，新增权限仍按正常授权处理。
5. 官方方法都失败则保留可复现步骤和版本，使用应用正式反馈入口。不能伪称本地已修复OpenAI内部实现。

完成依据：重启后能在同一正常连接中连续完成精确商品页导航、正文读取、截图、配色选择及第二商品页读取，且不再出现未附着/URL不确定停止。商品验收与工具稳定性分别记录，API通过不能替代浏览器恢复。

官方依据：[浏览器扩展排障](https://learn.chatgpt.com/docs/chrome-extension)、[Computer Use Windows前台使用说明](https://learn.chatgpt.com/docs/computer-use)，2026-10-31查阅。前者给出的恢复路径为核网站权限、应用更新、重启浏览器/核扩展、当前配置、新聊天、重启应用及正式重装/反馈。不要把它改写成“允许所有网站”或关闭安全检查的建议。
