## 1. 事实优先级

### 1.1 规则时效与冲突处理

本 SOP 中的货源真实性、单款事实、知识产权、平台合规、操作授权和发布回读属于 `HARD_CONSTRAINT`，不能因营销创意、竞品做法或短期数据而放松。商业基线是 `CURRENT_BASELINE`，以更新的单款证据或负责人当前确认覆盖。标题公式、关键词组合、主图顺序、图片风格、详情模块和历史运营习惯属于 `DEFAULT_HEURISTIC`，只作为起点，不得压过当前关键词/流量数据、平台现状、SKU 证据和负责人当前决策。

遇到新旧冲突时，先守事实、合规和权限底线；商品事实与接口限制按当前单款/平台证据，任务范围及可选策略按负责人最新明确决定。新授权不改变商品事实，旧任务限制也不覆盖已明确更新的授权。近期已验证经验优先于历史默认模板。先保护事实和合规，再说明为何调整；可复用的新经验应更新到对应 Skill 或本 SOP，单款试验只记录在单品档案。一次成功、一次失败或一个竞品页面不得直接升级为全店永久规则。通用迭代方法见 `../../.agents/skills/alibaba-international-operations/references/adaptive-operations-learning.md`。

负责人于2026-09-08确认：只有逐款关联原始数据包的商品属于贝强自有工厂货；已上线、API回读、图片、生成素材、热榜或竞品记录均不能证明自有工厂生产。负责人于2026-09-27补充确认：只要有与目标商品对应的真实鞋款和有效采购入口，即可在内部标为“已确认具备供货能力”，不要求采购页逐色逐码显示现货；外采货不得标成贝强自产。只有没有对应实鞋或没有有效采购入口的商品标记 HOLD_SOURCE（实物与货源待核验），不能计入已确认供给。采购入口不证明当日可供数量、固定价格、固定交期；接单仍须逐单确认可供色码、数量、报价、包装及交期。

负责人于 2026-09-24 明确纠正：**外采货号、供应商名称、来源平台以及“外部货源 / externally sourced / external supplier”等采购内部信息只写内部货源与发货台账，不得擅自写入阿里巴巴买家可见的标题、主图、详情、公司介绍或 FAQ。**商品页仍须真实，不得反向宣称该外采单款为贝强自产、专属产线、已有现货或已获特定定制能力。对未确认的 MOQ、混色混码、打样、包装、定制与交期，按买家需求确认和报价，不披露采购路径；如认为确需对外披露某种来源身份，先就具体商品、位置和文案征询负责人。内部风控标签与买家营销文案必须分层。

货源核验先于发布及推广：按商品ID → 型号 → 对应实鞋 → 有效采购入口建立供货能力对应；若要表述贝强自有工厂生产，另须逐款关联原始数据包。平台质量或内容验收只证明对应检查范围，不能替代实鞋或采购入口证据。缺实鞋或缺有效采购入口时标 HOLD_SOURCE；只要供货入口有效，无逐色逐码现货信息不构成改造的前置阻断。

单款唯一真源按以下顺序判定：

1. 当前款实物、原始数据包和负责人针对当前款的确认。
2. `01_产品资产/02_可发布素材/00_最终上传/BQxxx_货号/00_上架填写表.md`。
3. 当前款已验收图片、正式图片银行地址和本次执行载荷。
4. 平台草稿、复制态和线上态的回读结果。

旧商品、竞品和未经确认的通用模板只能提供页面结构，不能提供当前款事实。材料、尺码、颜色、价格、MOQ、库存、交期、包装、重量、定制、样品、清关和贸易条款均不得从旧商品默认继承；但下述负责人已确认的店铺商业基线可以按适用范围通用填写，不属于待清理的旧字段。负责人明确允许某批次继承商业字段时，材料、尺码、颜色和产品结构仍须逐款取证。

经营目标是有效采购商机及后续报价、样品和订单讨论；当前商品验收仍须官方实际评分 ≥5.0，并完成适用字段及公开验收。评分失败只按本次实际诊断修复，不自动新增永久禁令。标题、主图和详情优化按[现有竞品研究与页面方法](../../.agents/skills/alibaba-international-operations/references/product-page-strategy.md)直接推进，店内数据用于确定优先级和复盘，不以 A/B、固定试验款数或等待显著性作为前置条件。

FOB `8–12 USD/pair` 是当前商业目标区间，不是所有款的固定报价；最终报价取决于款式、数量、材料、尺码配比、包装和订单要求。

当前店铺商业基线（负责人于 2026-09-04 更新确认，并于 2026-09-23 再次确认包装值可通用填写）：MOQ `2 pairs`；现有线上价格梯度继续沿用；商机品结构化交期保持原值；单件包装 `34 × 23 × 13 cm / 0.5 kg / 1 pair`。修复旧商品时，保留或填入这组包装值，不把它列入“未核验旧包装”清理范围；只有单款数据包、实测或负责人后续确认不同值时才覆盖。这里是当前店铺填报基线，不表示已逐款实测，也不代表供应商实际包装已核实；接单前仍核对实际包装。买家侧产品亮点不得把结构化交期当作实际生产承诺，也不得统一承诺所有商品 3 天内发货；应表述为订单要求确认后尽快安排生产或发货，定制订单具体时间按材料、数量和定制内容在下单前确认。

商机品的 Excel 或 API 结构化发货期不是对定制订单生产周期的统一承诺，未经负责人针对具体批次确认不得修改。买家侧亮点、FAQ 和沟通文案使用灵活交期说明；平台要求多档预计天数递增，禁止为了通过校验编造梯度。

当前 GPSR 决策（负责人于 2026-08-17 确认）：暂时接受未关联 EU Responsible Person 所导致的指定欧盟国家屏蔽。不得把这一经营决定描述成 GPSR 已合规；未来恢复这些国家销售时，只能关联真实有效的欧盟责任人。

宽楦不是全店默认属性。BQ032 及以后产品按普通楦处理，除非当前款数据包、实物测量或负责人明确确认宽楦。禁止仅凭鞋头外观写 `Wide Toe Box`。

2026-10-03负责人补充选品与报价分析方向：比较真实拿货成本与国际站同单位、数量、规格/色码、定制、贸易条款和运费条件的报价空间；低价可能影响销量，未证明因果。沿用原30–50%成本加价规则，不等于净利润，实际服务及履约费用单列；未知费用待估，不阻断全部商品。当前不主攻1–2美元大批量低价基础款，不形成全店硬性售价下限。并列评估本款可兑现的质量、试单色码组合、响应/验货/英文资料等价值，未证库存、OEM或补单承诺不写。具体字段见单款任务包B项与现有页面策略；此次不更改任何已授权现货价格或广告预算。

## 2. 候选发现与三重去重

候选可来自本地原始数据包、贝强工厂店、工厂新款和国际站后台。每款先记录来源货号、图片、颜色、尺码和平台状态，再做：

负责人于 2026-09-22 明确授权：搜鞋网公开页面的搜索、商品页/店铺页访问、翻页、滚动、字段读取、截图取证和公开商品素材下载，均属于日常货源研究，可直接执行，不因访问本身暂停等待确认。该授权不包含登录或账户权限变更、联系商家、加入进货车、下单、付款、上传/一键上传，以及任何会改变外部状态的表单提交；这些动作仍按其实际外部影响与适用规则处理。

- 货号去重：相同厂家货号优先核验和优化旧链接，不新建第二个商品。
- 鞋型去重：比较鞋头、鞋面、闭合、后跟、外底几何、内里和尺码段；只换颜色或标题不构成新款。
- 买家意图去重：必须能说明该链接服务的独立采购需求。与现有链接完全相同则合并、暂停或替换弱链接。

Schema 新建发布前复用[既有工具入口的本地差异化检查](../../08_工具链/01_业务脚本/国际站扩品/README.md#发布前本地差异化检查)，对照现有来源登记、保存的商品快照和首图审查。报告冲突产品ID及字段；缺证标未验证，不从同源URL、标题换词或型号后缀推断新款。不为该检查重复拉取全店，不自动改商品状态。

不以“多发链接”规避违规或追求虚假数量。每个新链接必须具有真实产品差异、不同采购意图或独立结构证据。阿里巴巴国际站公开规则明确：同一产品仅改标题、图片、型号、非关键属性、尺寸、颜色、数量或组合后再次发布，仍可能被判定为重复铺货；不得用这些变化制造第二个链接。可独立发品的差异必须落在真实可供货的鞋面结构、外底结构、闭合方式、保暖/内里结构、功能用途或其他关键产品事实，并保留来源证据。

既有 HR 系列按负责人确认的编号结构解释：不带字母的 `HRxxx` 是产品/型号家族，`HRxxx-A/B/C…` 是该同一产品已经存在的不同国际站链接，不得因字母后缀把它们误判为不同鞋款或分别换成其他货号。处理这类已有流量链接时，不再新增同款链接；先统一真实货号、鞋型、颜色、尺码、SKU、来源和价格底线，再保留链接级的真实搜索意图、首图构图、图片信息角色和文案侧重点差异。差异化表达不能伪造成产品差异，也不能解除平台重复铺货风险；若平台提示重复、降权或违规，保留证据并暂停该链接，交由负责人决定合并、下架或继续保留。现有家族映射以产品经营主表和当次负责人确认优先。

负责人于 2026-09-23、09-24 补充：旧 HR 概念鞋不必强求完全同款；有可采购的**相似方向真实鞋款**即可按整家族替换，不能因不完全同形就无限期停在搜索。可以快速检索完全同款；没有明确结果就直接转向鞋型、用途或采购意图相近、资料足以重建页面的在售实款，而不是把“相似但不同”判为失败。先确认具体货号、可访问的下单或联系渠道、可供选择的色码与真实鞋图；**不要把“找到完全相同旧鞋”或供应商逐色逐码现货数字作为选品门槛**。页面显示 `0`/“无库存”/“是否库存：否”时，不据此直接淘汰，也不为核精确库存反复停工：若货号在售且公开页有有效拿货、代发、下单或联系入口，即可作为采购渠道继续页面改造；只有链接已下架、入口失效或已明确不能接单且找不到同货号替代渠道时，才不能视为当前可执行货源。仅在当次负责人明确要求写入库存且当前接口支持时，对指定有效 SKU 写 `999`；当前 API 新建批次可省略可选库存字段，不为评分补写库存。`999` 仅是可询货标记，不是实物库存、保供数量或对买家的现货承诺；接到具体订单时再核价、可供色码与数量、无标、包装和交期。替换必须让 A/B/C 共用同一货号，并按新鞋实拍重建鞋帮、闭合、颜色尺码、SKU、型号、图文和报价；旧概念图不能与新货号混用。不同 HR 家族还须做鞋型/采购意图去重，不能把同一货号重复包装成不同产品。不能把页面人气当国际站销量。

### 2.1 单款经营任务包与执行顺序

完整选品、换款或页面改造沿用[工厂店外新款数据采集模板](../05_扩品工程/工厂店外新款数据采集模板.md)，在单款既有执行目录填写；窄范围修改只填相关字段，不启动整套研究。模板是本 SOP 的执行记录，不建立第二份规则。按以下链条推进，并保留每一步的证据日期、边界、状态和唯一下一动作：

1. **需求与供给分开核验**：海外公开成交/近期购买提示、评价量、品牌榜单及后台买家词分别记录。近期购买提示只适用于原页面与观察期；评价量、品牌榜单是方向代理信号，不能证明本款销量。与具体搜鞋实款匹配关键结构、真实色码、材料、采购入口和可见质量依据；竞品认证、性能与工厂身份不能迁移。
2. **关键词到标题可追溯**：核心品类词、属性长尾词、采购服务词逐项记录来源/日期/市场、是否实际买家查询、搜索量及 SKU 支持。没有量化数据写“搜索量未知”；词汇出现不证明高流量或低竞争。标题说明选词和弃词依据，遵守当前字段限制与批次例外。
3. **图文回答采购问题**：逐张记录买家问题、可见证据、原图/裁切有效像素、文字边界与下一步。图数按 §4 的当前默认及单款例外；各图分别承担搜索识别和不同采购判断，产品详情回答规格、结构、选择和询价输入，公司图用已核实适用的整套版本。全组不用价格标签、数量价格卡或纯文字占位凑数。供应商可选问答或未宣传的可选性能不硬卡；缺必填或拟宣传的关键事实才阻断对应字段。
4. **发布与验收分阶段**：复用当前已验证 OpenAPI、当前类目 Schema 和单一写入者；未知可选字段可省略，未知必填只用当前 Schema 接受且真实的未知口径，否则待补证。接口提交、正式字段、审核、实际质量分及公开买家页分别回读。任何目标值、计划或工具外层成功都不能代替真实结果；关键词须核实持久化，不能只看本地文案。
5. **经营收尾显式登记**：新建、优化、替换、试验分别标角色。换款任务登记旧新 ID 映射、当前旧品分类/保护状态、授权范围与下架计划；新款验收后才执行已授权普通旧品收尾，再回读旧品状态。受保护链接不得混入批量收尾；下架不等于删除，省略库存不等于下架。不凭标题相似猜映射、不忽略冲突旧品来制造去重通过；未指定替换对象记“未分配”，不能宣称整店替换完成。若当前工具尚未实现所需映射/收尾，明确交给工具负责人，不伪造已支持。

已有成熟证据按方向与适用性复用并记录原采集日和本次核对日；只补会改变本次决策的缺口，不机械重扫热榜。无准确款型需求证据或无竞争量化数据的“蓝海”只能列为试验假设；记录测试链接、观察窗口与曝光/点击/询盘判断依据，不把假设写成热卖事实。完整业务完成要求所有适用环节结束；内容/评分/公开页通过可单独报告，不掩盖关键词或旧品收尾待办。

风险状态：`HOLD_IP`、`HOLD_FACTS`、`HOLD_ASSETS`。任何一项未解除都不得进入提交。

### 系统尺码自动换算与自定义尺码（2026-08-23 实测）

## 6. 商详结构与已知异常

完整发布包图数按 §4 当前默认及具体例外执行；当前模板的容量须单独核对，内部默认不等于全平台永久要求，图片角色也不永久固定。每张图必须回答不同的买家决策问题，角色可根据当前 SKU、目标买家和证据重组，但整组至少覆盖产品识别、真实选择/结构信息、采购支持和供应商信任，不得重复凑数。商业内容必须是已确认事实。公司图也必须逐张按 SKU 适用性检查；含 `Wide Toe Box`、固定鞋底材料、固定 DDP/税费/清关、Amazon、时效保证、个人联系方式或详细地址的图片，不得作为全店通用公司图。历史 `*_safe.png` 只作为已知低风险候选，不因文件名或旧审计自动成为最佳视觉；每次仍须按当前买家问题、信息价值和事实准确性重新验收。

- 产品详情图和公司图必须通过“买家问题—图片角色”语义验收，不能只检查数量、分辨率和 CDN 地址。产品图整组应覆盖当前买家最关键的产品识别、真实选择/结构和采购行动问题；公司图整组应覆盖当前最关键的供应商身份、定制沟通、生产组织、质量检查或包装交付问题，具体分配以本款证据和目标买家为准。同一批鞋架、库存、生产线或检查场景换角度重复出现，仍按冗余图处理。
- 产品亮点先写当前款可证明的事实，再写已确认且适用于本款的采购支持。公司能力与外采单款能力分开；未经本款确认不写自产、工厂直供或已具备OEM能力，可邀请买家提供Logo、色码、数量和包装需求后核实报价。不得统一承诺最低价、3天发货、认证或产能。
- 公司证明模块必须少而有证据：一张图片只承担一个主要角色，优先使用真实厂房/车间、定制沟通、生产、质检、包装各一项。不得把四张近似鞋架或库存照片拼成一页，也不得用泛化文案重复描述同一能力。
- AI 可用于受证据约束的背景清理、构图、光线、信息排版和有限补景，但不得把生成内容当作事实证据。鞋型、结构、颜色、数量语义、厂房建筑、设备、产能和流程均须与真实来源一致；无法从来源确认的建筑补全或工厂场景标记 `FACT_CHECK_REQUIRED`，经负责人确认前不得进入买家页。所谓“更好看”不能替代同屏事实对照和买家信息价值验收。
- 颜色 SKU 验收必须核对 `颜色名称 → 原始证据图 → 正式 CDN → API 回读`，公开页点击结果按 §5 的适用批次规则取证。只要图片 URL 可访问、数量正确或同属当前款，都不能代替颜色语义正确；每个颜色图必须肉眼可识别为其标签所写的那个颜色。未实际点击的商品不登记公开交互通过。
- 制作与审查分步骤：先整理来源、素材和机械校验，再逐色看图、判断买家价值与事实一致性；写后核正式回读和公开像素。单agent可依次完成，不以必须另派代理作为门槛；角色数量服从当次任务。

若草稿回读显示 `productDescType=2`（普通 HTML 详情），不能只核对结构化 `detailImage/companyImage` 数量。提交前必须枚举 HTML 中全部图片 URL，确认每一张均为本公司图片银行正式 Alibaba CDN 地址；临时地址、外部地址、其他店铺地址或仅能 HTTP 访问但不属于本店图片银行的地址都必须替换。2026-08-24 BQ041 实测表明，此类错误会在最终提交时被平台直接拦截。

- `productDescType=4`：按结构化 `detailImage/companyImage` 数量和 URL 验收。
- `productDescType=5`：结构化列表可能返回 0，但 AI/HTML 页面仍存在；必须读取 pageId/HTML 或买家公开页，不得仅凭结构化计数判定丢失。

- 结构化纯图片图库不得写入 `imageText`。2026-08-25 BQ010 实测表明，产品图集 `150/200/300/350` 与公司图集 `400/450/500/600/700/750` 等纯图片组带说明时，卖家编辑页会弹出“详情图集文本说明处理提示”，阻断预览/提交；只有页面明确标注“支持添加文本”的图库才允许保留说明。清除说明必须先在 `draft` 层回读图片数量、顺序和 URL，再提交。
- 正式图片 URL 必须验证完整结构 `https://sc04.alicdn.com/kf/<无扩展名的图片ID>/286385890/<图片ID>.<扩展名>`。仅检查 Alibaba 域名或 `/286385890/` 不够；`<图片ID>.png/286385890/...` 这类扩展名进入目录的嵌套 URL 会被接口表面接收并形成重复图，必须在提交前拦截。

- “同步至 App/无线端”会覆盖移动端原有详情且平台提示无法撤销。实测它不是 PC 公开 `bodyLayout` 重建的必要步骤；没有独立移动端需求或负责人授权时不得执行。负责人已于 2026-08-25 明确授权批次 1 同步及后续同类常规同步动作可直接执行，因此同一已验收 PC 详情可按授权同步，不再逐款确认；但同步前仍必须保证 PC 公开终验已通过。实测流程为：唯一商品编辑页 → `AI商详一键装修`（必要时第一次点击仅加载编辑器，须等待 `decorateDetailEditor` 出现）→ 编辑器内 `同步至无线` → 选择免费 `通用排版` → `生成同款` → `保存` → `编辑完成`。禁止选择带 i豆费用的模板。2026-08-26 实测发现，保存后的编辑器有时残留 `aria-hidden=true / fadeOutUp` 的已关闭确认层，继续点击会被透明遮罩拦截；此时不得反复空点或新建商品，应关闭该编辑页，按同一 `productId` 新开唯一编辑页，再进入 `AI商详一键装修`，先触发 `同步至无线`，随后执行免费通用排版的生成、保存和编辑完成。后台商品分组名称可能包含旧定位词，风险扫描时必须区分分组字段和详情正文，同时把不准确分组另列为待治理项。

- AI 详情编辑器的 DOM 图片先后顺序不等于结构化图库归属。替换前必须逐个读取图片节点的 `data-component-group-name`，按 `product-gallery` 与 `company-gallery` 的真实归属绑定；禁止按视觉位置、DOM 序号或文件名猜测分组。保存后必须再次回读两组计数与 URL，再进入外层提交。
- 卖家端 `sellPreview` 已是新文案，但公开 `descIframe` 仍是旧文案时，状态只能记为“已提交，待审核/同步”。不得把卖家预览、`copy` 或同值 `trunk` 单独当作线上 HTML 生效证据，该目标仍待验收；其他不受影响的已授权制作可继续。
- 公开详情验收必须同时检查 `descIframe` 正文和每一张图片的真实像素内容。DOM 风险词扫描只能发现可访问文本，不能发现已经写进图片中的旧款鞋、宽楦、退款、物流、第三方品牌或错误尺码；必须逐张打开/下载预览并确认图片角色、SKU 身份和图内文字。图片数量正确但内容错误仍判定失败。
- 公开像素验收至少覆盖：6 张主图、全部产品详情图、5 张公司图和每个颜色唯一 SKU 图。`GLOBAL SHIPPING SOLUTIONS`、DDP、Amazon FBA、`WORLDWIDE DELIVERY AVAILABLE`、固定到门/清关/税费承诺等即使只写在图片内，也必须删除或替换为“按当前订单、目的地和买家指定货代确认”的安全表达。删图后按 §4 当前默认及例外核信息完整性，不为凑数保留风险图。
- 旧 HTML 文案修复后同时扫描英文和平台自动翻译文本：`refund/deduct/退还/抵扣/扣除`、无依据的 `wide toe/roomy toe/宽楦/宽敞鞋头`、通用 `Flyknit/飞织`。仅当前 SKU 证据支持的产品级表述可以保留。
- 错误临时地址已进入草稿且 DELETE 回读不生效时：浏览器逐组清空并保存空草稿，再写入正式 CDN；不反复追加。
- 共享模板、图库或结构化升级变更须登记所有受影响绑定ID并核公开正文及像素；未覆盖影响集不报该批完成。独立局部修改只核目标及关联字段，范围按 §9，不以每批全店重扫为默认。

- 浏览器清空结构化详情图集时，点击“删除全部”只会打开确认层，不代表图片已删除；必须实际点击可见的“确认删除”，并以页面总数变为 `(0/30)` 为准。若先取消图集勾选再重新勾选，平台可能恢复隐藏旧图，因此应在目标图集保持勾选的状态下再次核对计数，再上传正式图片。点击外层“保存”后若出现“详情图集文本说明处理提示”，必须点击可见的“清除并继续”；随后另开一个全新的原商品草稿页，回读图片数量和重复图告警。只有新页仍为预期数量且无重复告警，才能点击“提交”。
- `copy` 正确而 `trunk` 仍旧表示审核切换中，只能记录“已提交修复”，不能写“线上已生效”。
- SKU 写入后必须回读 `draft.sku`，核对总数、颜色集合、尺码最小/最大值和特殊尺码限制；接口返回的 `skuId=0` 是新草稿规格尚未分配正式 ID，不等于写入失败。

- 同一商品由唯一写入者顺序更新相关模块并回读，避免旧快照覆盖新值。详情升级须检查带入的旧文案/图库；已有ID不重建，替换按当前支持接口及正式差异核验，不照搬退役命令。历史异常证据仍保留在原执行目录。
