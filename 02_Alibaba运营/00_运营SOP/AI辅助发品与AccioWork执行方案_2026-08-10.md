# AI 辅助发品与 Accio Work 执行方案

## 结论

AI 可以帮助贝强完成约 80%-90% 的发品准备工作；Accio Work / Work Agent 从能力设计上可以处理商品查询、素材包解析、类目预测、属性/SKU 映射、预检、草稿和发布任务。但最终发布必须保留人工确认关口，尤其是材质、尺码、价格、MOQ、包装、交期、定制和物流字段。

## 推荐工作流

### 阶段 1：AI 整理本地数据包

1. 识别新包和已有商品的重复关系。
2. 提取型号、颜色、尺码、鞋面、鞋底、闭合和图片证据。
3. 清除尺寸重复图、国内电商详情图和不合规文案。
4. 生成 `00_上架填写表.md`、6 张主图计划、颜色 SKU 图和英文详情页任务单。

### 阶段 2：读取现有线上商品

1. 拉取在售商品 ID、标题、状态、类目和质量分。
2. 拉取目标相似商品的完整字段、SKU、主图、详情、价格、包装和交期。
3. 对比新款与现有商品，决定新发、并入 SKU、延后或放弃。
4. 查询最近 7/30 天曝光、点击、CTR、询盘和商机，选择真正值得扩展的方向。

### 阶段 3：生成草稿

1. 让 Work Agent 解析素材包并预测类目。
2. 将本地填写表合并到平台草稿，不让工具自行猜高风险字段。
3. 执行发品预检。
4. 输出字段 diff：标题、关键词、属性、SKU、主图、详情、价格、MOQ、包装、交期。

### 阶段 4：人工确认

必须由用户确认：

- 发布商品和目标类目。
- 材质、尺码、颜色和 SKU。
- 价格、MOQ、样品、包装、交期和物流。
- 将创建草稿还是直接发布。

### 阶段 5：发布与回查

1. 优先发布草稿或单款商品，不做未经审阅的批量直发。
2. 发布后只读回查所有关键字段。
3. 7/14/30 天记录曝光、点击、询盘和买家问题。

## 三种使用方式比较

| 方式 | 自动化程度 | 风险 | 建议 |
| --- | ---: | ---: | --- |
| AI 生成填写表，人工后台录入 | 中 | 低 | 适合最初 1-3 款，便于建立正确模板 |
| AI + 浏览器辅助填写，发布前停下 | 中高 | 中 | Accio Work 不稳定时的备用方案 |
| Accio Work 素材包草稿 + 预检 + 人工确认发布 | 高 | 可控 | 推荐目标方案 |
| 未审阅批量直发 | 最高 | 高 | 不采用 |

## Accio 标准任务提示词

### 任务 A：全店商品只读核验

```text
这是只读任务。查询当前阿里巴巴国际站店铺的全部已发布商品和草稿，输出：productId、型号、完整标题、叶子类目、产品分组、状态、质量等级/PIS、主图数量、视频、关键词/卖点完整度、核心属性、SKU、价格区间、MOQ、包装、交期、近30天曝光、点击、CTR、询盘。检测标题重复、关键词空缺、模板化字段和标题/属性/图片矛盾。重点核验 R1601 是否仍存在标题 Canvas 与 Upper Material=Stretch Fabric 的冲突。把商品分成：保留推广、优先优化、合并/暂停、证据不足四类。不要编辑商品、不要创建草稿、不要发布、不要发送消息。无数据字段明确写“未返回”，不得猜测。
```

### 任务 B：BQ031 素材包发品预检

```text
这是只读预检任务，不创建草稿、不发布。读取贝强工作区：01_产品资产/02_可发布素材/00_最终上传/BQ031_ZX2116，并以 00_上架填写表.md 和真实图片为事实来源。完成：与现有商品去重、类目候选、标题/关键词建议、必填属性清单、SKU颜色映射、主图与详情页合规检查、发品预检、缺失字段和风险列表。已知方向：ZX2116、宽头/大码38-47方向、五种颜色、针织鞋面、EVA软底证据、约187g/只的图片证据。材质、尺码表、MOQ、价格、样品、包装、交期、定制和贸易条款如未确认必须标记待确认，不得补猜。输出“可直接使用字段/必须确认字段/禁止使用字段/预检阻塞项”。
```

### 任务 C：RFQ 与客户开发只读方案

```text
这是客户开发只读任务。检索近12小时与 wide toe box walking shoes、comfort walking shoes、lightweight slip-on shoes、breathable knit casual shoes 相关的国际站 RFQ；结合贝强定位筛选美国和欧洲市场的进口商、批发商、Amazon/TikTok卖家、品牌/private-label买家和采购代理。输出 RFQ标识、国家、采购品类、数量、关键要求、发布时间、匹配产品方向、A/B/C优先级、推荐回复结构和仍需确认的报价数据。不得自动报价、不得发送消息、不得承诺FOB最终价格、MOQ、交期或证书。过滤零售消费者、医疗/矫形承诺和明显不匹配需求。
```

## 结果沉淀规则

每次 Accio 任务完成后，必须把结果保存到工作区，而不是只留在聊天记录：

```text
02_Alibaba运营/01_店铺与全店诊断/Accio全店只读核验_YYYY-MM-DD.md
02_Alibaba运营/02_单品优化记录/BQ031_Accio发品预检_YYYY-MM-DD.md
04_客户开发/01_线索与CRM/Accio_RFQ筛选_YYYY-MM-DD.md
```

每份记录必须包含：

1. 数据窗口和账号/店铺口径。
2. Accio 实际返回的事实与未返回字段。
3. 商品 ID、任务 ID 等本轮上游标识；不得跨轮猜测复用。
4. 成功步骤、失败原因和恢复入口。
5. 本次新知识、与旧结论冲突的地方、下一步动作。
6. 是否发生线上写入；没有写入时明确标注“只读”。

后续更新长期规则时，优先修改本 SOP 和对应的单品/全店记录，避免新增多个互相冲突的零散文档。
