# BQ 低曝光款主图诊断与改造方案（灰度批次）

- **日期**：2026-09-28
- **范围**：BQ 系列**曝光 ≤ 20 的商品 54 款**（其中**零曝光 31 款**）
- **选样理由**：负责人指定灰度原则 —— 改最低曝光款风险最小、最可能验证效果；不动已有高曝光商品
- **数据源**：阿里开放平台 `product.get` 主图 URL（54/54 下载成功）+ 数据管家流量导出 + 热榜对比图

---

## 一、先复述我从项目里读到的原有指导思想

在动手之前，我读了项目里关于主图的全部沉淀。**原有逻辑本身是成熟的**，核心是三层：

### 1. 六图决策漏斗（M1–M6）

```
找到我 → 看懂我 → 相信产品 → 知道怎么采购 → 判断SKU空间 → 相信供应商
  M1       M2        M3          M4              M5            M6
```

- **M1 白底搜索首图**：回答"这是不是买家在找的产品"。真实鞋体、白底、完整、大主体、易识别 3/4 角度。**不承担** OEM、参数、工厂、功能、认证
- **M2–M6**：不是同一鞋面/同一颜色/同一卖点的重复展示，整组要帮进口商完成**不同**采购判断

### 2. AI 的定位（这条最硬）

> **AI 只能是 `Visual Enhancement Tool`，不能成为 `Evidence Creation Tool`。**

允许：抠图、白底、去污、曝光/白平衡、清晰度、自然接触阴影、轻微透视与构图。
禁止补造：鞋底纹路、鞋垫、内部结构、针织纹理、缝线、标签；设备、工人、厂房面积；MOQ、产能、认证。

### 3. 三证据等级

`VERIFIED`（可发布）/ `CONDITIONAL`（只能条件化表达）/ `UNKNOWN`（不得进入正式视觉）

> 每张正式图必须回答：图中每个事实可以回溯到哪一张原图、哪份资料或哪次确认？回答不了就不发布。

**这套逻辑没有问题。问题出在执行层。**

## 二、历史债务是怎么形成的（你说的"信息传递中丢失价值"）

我把项目的沉淀按位置列出来，问题就清楚了 —— **同一主题的知识分散在三处，彼此没有交叉引用**：

| 位置 | 文件 | 性质 |
|---|---|---|
| `.agents/skills/` | `image-brief-generator/SKILL.md` | 出图简报生成 |
| `.agents/skills/` | `image-conversion-review/SKILL.md` | 图片转化审查 |
| `.agents/skills/alibaba-international-operations/references/` | `ecom-image-generation-lessons.md` | 生成经验 |
| `07_知识库与Skills/05_项目记忆系统/preferences/deliverables/` | `buyer-facing-factory-image-preference.md` | 偏好 |
| `07_知识库与Skills/05_项目记忆系统/preferences/deliverables/` | `alibaba-multilink-image-and-title-preferences.md` | 偏好 |
| `07_知识库与Skills/05_项目记忆系统/knowledge/experiences/` | `alibaba-multilink-visual-failure-2026-08-28.md` | 失败经验 |
| **`02_Alibaba运营/02_单品优化记录/BQ系列持续优化_2026-09-14/`** | **`鞋类B2B商品视觉方法论_网页版GPT讨论结论_2026-09-16.md`** | **通用方法论** ← 位置异常 |

**最后一个尤其说明问题**：一份**通用**视觉方法论，被放在**某个单品的优化记录目录**里。后来的人要找视觉规范，不会想到去 `02_单品优化记录/BQ系列持续优化_2026-09-14/` 下面翻。

### 更关键的是：规则与校验脱节

`批次01-08主图质量阻断审计（2026-08-30）` 自己写明了根因：

> 旧 Excel 校验**只验证六张 URL 唯一、详情图不重复以及 URL 属于阿里图片银行**。
> **校验没有识别中文文案、国内促销图、颜色拼图、电子秤、场景道具、第三方标识和首图职责。**

而项目里**早就有**规则：「原始数据包只是证据源，不等于可发布素材」。

**结论：规则在文档层存在，但执行层（脚本 + Excel 校验）只检查"结构性唯一"，不检查"内容质量"。** 于是：

- 105 条链接里 **100 条首图来自原始数据包**
- **96 条链接的六图全部来自原始数据包**
- 直到人工预览才发现问题

**这就是债务形成的机制：规则 → 无人执行的文档；校验 → 只查 URL 不查内容。** 后来者看到的是"绿灯通过的 Excel"，而不是"规则"。

## 三、实测：这 54 款的主图实际状况

我对 54 款全部下载了 M1 首图，做了量化 + 抽样目视。

### 3.1 好消息：底子比预期好

| 指标 | 结果 |
|---|---|
| 干净白底 | **48 / 54（89%）** ✅ |
| 首图被多款共用 | **0 款**（多链接首图确实做了区分，符合项目规则）✅ |
| M6 公司能力图共用 | 29 款共用 1 张，**位置均为第 6 位** ✅ 符合设计 |

**这修正了我原本的预判** —— 我以为低曝光款图很烂，实际不是。

### 3.2 真问题（按严重度）

**① 型号码/信息标签印在首图上 —— 36 / 54 款（67%）** ⚠️ 最高频

实测例子（我逐张看过）：

```
BQ001-S2   → 顶部蓝底白字「BQ001 | WHITE」+ 底部「WIDE TOE BOX | SLIP-ON」
BQ003-S1   → 顶部「R1218 · WHITE」+ 底部「WHOLESALE · OEM / ODM」
BQ006-S1   → 顶部「M8811 · ALL WHITE」+ 底部「WHOLESALE · OEM / ODM」
BQ007-S1   → 顶部「L0017 · WHITE」+ 底部「WHOLESALE · OEM / ODM」
```

**三重违规**（按项目自己的标准）：

1. **M1 规定了"不承担 OEM"** —— 但底部写着 `WHOLESALE · OEM / ODM`
2. **`image-brief-generator` 要求首图 "clean, product-first, with minimal or no text"**
3. **`image-brief-generator` 明确："B2B 标识必须对应具体信息，不做装饰性徽章"** —— `WHOLESALE · OEM/ODM` 是纯装饰

而且**型号码对买家毫无意义** —— 这正是你之前指出的："标题里不用保留型号，我看人家卖的都没这种信息"。**主图上更需要去掉。**

**② 场景图混入首图 —— 3～6 款** ⚠️

| 款 | 实际首图 | 违反的既有规则 |
|---|---|---|
| **BQ023-O1** | **手持鞋 + 真人腿（牛仔裤）+ 咖啡店橱窗** | 审计明列"模特脚、手持、场景道具" |
| **BQ022-O1** | 双鞋放在**灰色台阶石板** | 门禁第 3 条"干净浅色背景" |
| **BQ036** | 水泥地场景 + 顶部 5 个信息点长条 | 同上 + 装饰徽章 |
| BQ025-R1 / BQ048 | 背景偏色（灰/棕） | 门禁第 3 条 |

**③ 风格三套并存**（我在抽样中确认）

- 卡片式（浅色渐变 + 圆角白卡 + 上下角标）— BQ001/BQ003/BQ006/BQ007 家族
- 纯白双鞋（无角标）— BQ032-O1 等
- 场景式（手持/台阶/水泥地）— BQ023-O1/BQ022-O1/BQ036

同一店铺、同一品类，首图风格不统一，会削弱"专业供应商"的整体观感。

### 3.3 关于"同款多链接"的结构性发现

31 款零曝光**全部**是同款多链接的变体：

| 家族 | 链接数 | 家族六图唯一数（满分=链接数×6） |
|---|---:|---:|
| BQ006 | **7** | 36 / 42 |
| BQ007 | 6 | 34 / 36 |
| BQ005 | 6 | 33 / 36 |
| BQ002 | 5 | 28 / 36 |
| BQ003 | 5 | 26 / 36 |
| BQ004 | 4 | 21 / 36 |
| BQ001 | 3 | 16 / 36 ← **最低** |
| BQ032 | 3 | **12 / 36** ← **最低** |

**表面看：首图各自独立（合规）。但鞋型完全相同、标题品类词相同、M6 共用。**

按项目自己的 `image-conversion-review` 判定标准：

> Classify `5/6 shared main images + all product-detail images shared` as high-confidence duplicate-presentation risk.

我们的重合度**未达到 5/6 全部共用**，所以不构成项目定义的高置信度重复。但**同款 5–7 条链接同时零曝光**，这个组合本身值得警惕。

**我的判断（标注为推断）**：零曝光的**根因可能不在主图质量，而在"同款多链接"策略本身** —— 平台面对 5–7 条外观近乎相同的链接，只可能给少数分配曝光。**先把主图改好是必要的，但不一定充分。**

这个我不下定论，需要下一批数据验证（见第六节）。

## 四、对比热榜：差距不在"好看"，在这三条

我从数据管家抓了热榜/热门关键词商品卡的主图（10 张 800×800）对比。

| 维度 | 我们（低曝光款） | 热榜 |
|---|---|---|
| **背景** | 浅蓝/浅灰渐变 + 圆角白卡 | **纯白** 或 **强场景**（鞋盒开箱、暗调反光台） |
| **产品占比** | 产品被圆角边框和文字条挤压 | **产品几乎充满画面**，贴边 |
| **画面上文字** | **内部型号码 + 装饰徽章** | **无** | 
| 场景处理 | 中间态（不够干净也不够有场景感） | 二选一，做到极致 |

**最扎眼的一条**：热榜首图**不出现任何内部信息**。而我们的首图顶部印着 `BQ001 | WHITE`、底部印着 `WHOLESALE · OEM/ODM` —— 在搜索缩略图尺寸下，这些字占了黄金视觉位，**挤掉的是鞋本身**。

## 五、改造方案

### 5.1 图片层（低成本、可立即做、风险最低）

| # | 动作 | 涉及款数 | 依据 |
|---|---|---|---|
| 1 | **移除首图上的型号码标签** | **36** | 热榜 0 出现；M1 规定不承担 OEM；买家不关心内部编号 |
| 2 | **移除装饰性 `WHOLESALE · OEM/ODM` 徽章** | 36 | `image-brief-generator`："不做装饰性徽章" |
| 3 | **场景图重做为干净白底** | 3～6 | 门禁第 3 条"干净浅色背景" |
| 4 | **背景偏色修正为纯白** | 2 | 门禁第 3 条 |
| 5 | **统一为纯白底 + 大主体 + 3/4 角度** | 全部 54 | 热榜主流做法 |

> ⚠️ 以上全部属于项目规则**明确允许**的 AI 操作（抠图/白底/去污/构图/统一画布），**不触碰"不得补造"红线**。原始实拍图作为事实锚保留。

### 5.2 策略层（需要你决策，不是我能定的）

31 款零曝光全部来自同款多链接。**图片改好后，如果曝光仍为 0**，那就验证了"同款多链接被平台判定重复"的假设。届时要决定：

- 每个家族**保留 1–2 条主链接**，其余合并或下线？
- 还是继续维持多链接，只是把差异做在**颜色 + 买家意图**上（项目 `alibaba-multilink-image-and-title-preferences.md` 的原意）？

**我建议先做图片层，用这批零曝光款当实验组** —— 这正是你说的灰度原则。

### 5.3 知识层（治"历史债务"的本）

你提到项目里"冗余和丢失价值"，我建议做一件小事：

1. **把 `鞋类B2B商品视觉方法论_网页版GPT讨论结论_2026-09-16.md` 从 `02_单品优化记录/` 移到 `07_知识库与Skills/`** —— 它是通用方法论，不该埋在单品目录里
2. **在两个 skill 与方法论之间加互相引用** —— 现在三处知识互不相认
3. **把"主图门禁"从人工预览变成可执行检查** —— 这是 2026-08-30 那次事故的真正教训：规则写在了文档，校验只查了 URL。可以固化成脚本字段（如 `visual_qa` 必须人工置 PASS 才能导出），而不是靠"记得去看"

## 六、我建议的下一步（灰度验证）

| 阶段 | 动作 | 观察指标 |
|---|---|---|
| **第 1 步** | 挑 **8–10 款零曝光**做白底 + 去文字改造 | 搜索曝光是否从 0 变正 |
| **第 2 步** | 观察 7–14 天 | 曝光 / 搜索点击率 |
| **第 3 步** | 若曝光转正 → 批量推 54 款；若仍为 0 → 转向策略层决策 | |

**注意**：机制分析已证明**商机由曝光规模决定**，而曝光主要来自付费推广。所以本批次的观察目标应设为 **"曝光是否从 0 变正"**，而**不是"是否拿到询盘"**。
