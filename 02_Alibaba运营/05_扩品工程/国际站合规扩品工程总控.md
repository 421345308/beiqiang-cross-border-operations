## 五、链接布局与规则

1. 上齐真实独立鞋型，用不同结构、人群、闭合和尺码段扩大搜索覆盖。
2. 不把同一鞋仅换标题、主图、详情页和关键词后重复发布。

5. 发布后以曝光、点击、CTR、询盘数和询盘质量决定优化，不因零曝光继续制造重复链接。

## 七、后台实测沉淀（2026-08-15）

### 1. 图片与规格

- 上传前把本地文件统一加上 SKU 前缀，例如 `BQ033_01_main.jpg`。图片银行中通用文件名会产生错款风险。
- 图片银行可能按相同内容去重并保留另一个文件名；选择时以画面内容和 SKU 前缀双重核对。
- 国内数据包每张图必须在上传前人工可视化检查：中文促销字、国内节日文案、乱码英文、第三方标识、买家评论和未确认功能图不得直接上传。
- 不得为了去字让 AI 重画鞋型、编织纹理或外底；若风险文字在边缘，优先做确定性裁切并再回读画面。BQ035 主图 03 即采用裁切去除无关乱码英文，且未改变产品结构。
- 颜色值必须从平台下拉中确认并按 Enter 落值；仅输入或失焦可能在保存后回退。
- 颜色、标题、型号、主图顺序和 SKU 图完成后必须“保存 → 重载 → 回读”，不能只看当次页面。

### 2. 页面遮挡

- 右侧 AI 助手抽屉和客服浮窗会透明覆盖规格图片或删除按钮，表现为按钮可见但点击无效。
- 操作前关闭 AI 抽屉；客服浮窗遮挡时先拖离目标区域，再执行图片银行或删除操作。

### 3. 结构化详情

- 结构化详情采用懒加载。重载后空容器不等于详情为空，必须先滚动到“商品详情信息”区域再判断。
- 复制旧款只允许复用版式。必须逐项替换产品亮点、型号、材料、尺码、颜色和产品图片，并扫描旧 SKU 残留。
- 本批标准产品详情为 6 张：产品概览、规格、尺码、颜色、订单支持、OEM 询盘；无新款素材的旧场景图模块直接删除。
- 编辑器保存顺序：`保存 → 编辑完成 → 确认同步 App → 主发布页保存 → 重载回读`。
- 最终门禁：详情预览中旧 SKU 命中数为 0、产品图为 6 张、平台质量分 5.0，才允许提交。

### 4. 提交与续跑

- 提交成功页的 `primaryId` 是商品 ID，以成功页和“审核中”状态作为提交完成凭据。
- 禁止把现有商品 URL 手工改成 `pubAction=similarPost`。实测该方式会复用源商品 ID，甚至在未点击“保存”时覆盖源商品内容。
- 浏览器复制只能从平台 UI 进入 `发布新商品 → 发布类似 → 选择源商品`；真正的新建链接 URL 使用 `opType=similarPost`。新草稿仍需检查是否获得独立 ID，提交后必须再用商品总数和商品列表回读证明没有覆盖旧链接。
- Accio/Workctl 优先采用 `最终素材 → CDN URL → materialInfo → infer/category schema → 草稿 → search 回读 → 属性纠偏 → publish-draft → 审核队列`。最终图片已制作完成时使用 `decorationPlan=none`，禁止 AI 重画或自动改写商品事实。
- 平台 AI 解析结果不能直接发布。BQ033 实测出现标题改写、Outsole=EVA、Lining=Mesh、Anti-Slip 和颜色 SKU 错配；必须以填写表和实物图为准回读并删除未确认字段。
- Workctl 草稿属性编辑采用 `attrNameId + attrValueId + attrValue + operationType`；已有属性用 `EDIT`，新增属性用 `ADD`。接口返回 success 后仍必须 search 回读，不能把成功回执当作字段已生效。
- 素材生成脚本重跑不得覆盖已上架/已提交/草稿待提交状态；脚本已改为保留超过 `ASSETS_READY` 的运营状态、下一动作和更新日期。
- Accio 重启、升级、任务切换或存在旧消息排队后，必须先只读查询目标 ID 的草稿/审核/在线状态及同型号匹配数，确认旧任务终止后再写入。BQ033 的重复审核商品即由旧指令延迟执行造成。
- `publish-draft` 发布预检是详情图真实性门禁。BQ036 首次预检返回 `detailImage:详情图片不能为空`；正确修复结构为 `operationType=ADD + newImageUrl + imageIndex`，旧结构 `[{imageUrl:...}]` 会出现接口成功但实际未落值。
- 下一款从 BQ037 开始；不要重新创建 BQ032-BQ036，也不要从未核验的旧款复制产品字段。
