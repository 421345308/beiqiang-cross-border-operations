## A. 详情页结构结论（四层对照：结构化字段 / 富文本路径 / 商详 HTML 数据源 pageId / 买家前台）

> **补充判据（2026-08-17 第二版）**：按外层补充要求，增加「前台商详 HTML 数据源」维度。`icbu.trade.list-product-page` 返回的 `description` 字段即买家前台描述区的渲染 HTML 数据源，其 `data-magic-global` 属性携带 **pageId**（模板实例标识）。**pageId 存在 + descLen>0 + 图片数>0 = 有完整 AI/HTML 商详**；pageId 缺失 + descLen=0 = HTML 商详为空。
> 说明：`pageId / descComponentData / bodyLayout` 字段名在当前 schema 的 `list-information`（trunk/copy，全组件）与 `list-id` 中**均不返回**（已实测 grep 0 命中；componentList 传这些名称报 unsupported）。当前 schema 下等价判据为 `list-product-page` 的 description HTML + pageId；`descComponentData/bodyLayout` 仅能在 HTML 中对应观察到模块结构。

### 关键机制：店铺存在两套详情模板（全量 40 款已核）

1. **A 类：HTML 富文本模板（descType=5，isAiEdit=true）→ pageId 存在，HTML 商详完整** — 34 款：BQ001–BQ032、BQ034、BQ035。
   - 结构化组件（detailImage/faqs/companyDesc/productSellingPoint 等）**全部为空**，这是 descType=5 的固有表现（内容存于 HTML 富文本路径），**不等于前台无内容**。
   - `list-product-page`：descLen 11.5–18.8KB、图片 6–16 张、pageId 全部存在；浏览器抽样（BQ031/BQ032/BQ034/BQ020）确认前台 iframe 内完整渲染（产品图 + 卖点/公司/尺寸/场景/FAQ 模块）。

## E. 能否在不重建商品的前提下修复？—— 可行

当前 workctl 动态 schema（v0.1.37）确认以下**只读命令之外**的写通道（仅列出能力，未执行）：

| 目标 | 命令 | 说明 |
|---|---|---|
| 标题/卖点/属性（含 Model Number attr） | `icbu.product.update-edit`（--editList） | 批量直接更新在线商品基础信息，**无需重建**；需 `--yes` 确认 |
| 详情组件（商详图 detailImage / 公司图 / 公司介绍 / FAQ / 卖点） | `icbu.other.product-edit-draft-detail`（--productId + --detailImage/--companyImage/--companyDesc/--faqs/--productSellingPoint） | 编辑**草稿**详情模块 → 再 `icbu.other.submit-draft` + `icbu.product.publish-draft` 提交发布；**不重建商品**（同一 productId 的草稿流） |

| 价格/MOQ/交期/包装 | `icbu.other.product-edit-draft-trade` / `product-edit-draft-fulfillment` | 同上草稿流 |

**结论**：BQ003–BQ024 标题/型号类问题可 `update-edit` 直接修复；BQ033/BQ036–BQ040 可通过 draft 链路（edit-draft → submit-draft → publish-draft）在同一商品上补齐 detailImage 组件与 SKU，**均无需删品重建**。注意事项：
