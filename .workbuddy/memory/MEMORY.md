# 贝强工作台 · 项目长期约定

## 工作区定位（2026-09-22 负责人确认）

**这个工作区是负责人个人所有项目的总和，不是「一家鞋业公司的资料库」。**

- 鞋类跨境 B2B 经营是其中**一条主线**，不是唯一目的。
- 通用能力建设（AI 视频、内容创作、工具链、其他项目）与经营主线**并行**，同等正当。
- **不得用「对卖鞋有没有用」作为筛选或裁剪任何通用能力的标准。**
- 一项能力若同时对鞋业经营有增益，是加分项，不是准入门槛。

落地含义：
- 通用能力的知识、Skill、工具放在工作区级位置（如 `07_知识库与Skills/04_AI视频知识体系/`、`08_工具链/`），不挂在鞋业 Skill 下面。
- 鞋业专用层只写**场景约束与改造方法**，不评判通用能力的价值。
- 约束属于**使用场景**，不属于能力本身。同一模板在通用创作里合法，在对外商品视频里可能违规 —— 要分开写清，不能因为经营场景的限制就把能力整体判为不可用。

## 第三方内容引入的三层法（2026-09-22 确立）

引入第三方能力库（如 awesome-seedance）时：

1. **L1 只读参考层**：第三方仓库落本地、加 `.gitignore` 不入库；只把**项目自己的索引**入库。
2. **L2 吸收层**：把结论吸收进现有 Skill，保持「一个权威」，不新建平行权威。
3. **L3 可选安装**：只装真正对口的第三方 Skill，安装前必须过安全审计。

已落地案例：`awesome-seedance`（25 模板 / 463 案例）—— 仓库在 `08_工具链/02_视频工具/awesome-seedance/` 不入 Git；索引在 `07_知识库与Skills/04_AI视频知识体系/awesome-seedance-模板索引.md`；鞋业场景约束在 `.agents/skills/beiqiang-seedance-video/references/template-mapping.md`。

## 与 Codex 并行操作 Git 的注意事项

- 本工作区常有 Codex 会话并行运行。**不要覆盖其他任务未提交的改动**，提交前先按顶层目录切分范围。
- `index.lock` 残留在本项目会阻塞 Codex 的 git 操作。只有确认**无任何 git 进程**、且锁为 **0 字节**时，才按项目先例清除。
- 沙箱内 `git` 网络操作会被静默拦截（exit 128 无输出），推送须在沙箱外执行。诊断顺序：先测公开仓库能否匿名拉取，以区分网络问题与认证问题。
