# 工作区维护

本页定义文件归属与维护方式；项目事实和专项执行规则分别由根 AGENTS、原始证据、业务 SOP 管理。

## 单一职责

| 内容 | 唯一维护位置 |
| --- | --- |
| AI 总入口与条件式门禁 | 根 AGENTS.md；专项规则放业务目录 AGENTS/SOP |
| 跨业务优先级 | 当前状态.md；只排工作与下一步，不抄逐款、逐客户数值 |
| 产品身份、款式来源、平台链接和待办 | `02_Alibaba运营/05_扩品工程/数据/产品与链接台账.json`；扩品总文件、查询页、兼容CSV由它生成，产品经营主表只路由 |
| 跨渠道方法与指标 | 跨渠道经营总览.md；不再保留过时“当前状态”表 |
| 全目录导航 | 资产索引.md；只指向有效入口 |
| 长期判断、已确认偏好 | 项目记忆库；正文一处、索引一行、按需读取 |

## 新工作如何落盘

- 负责人日常只看一个业务总文件。每次更新覆盖对应条目，Git承担普通修改历史；不得另建“本次修改”“项目整理_日期”“明早验收”“最新交接”来重复描述当前结论。确有独立采集、交易、发布或测试发生时才留对应原始证据，总文件只链接证据。
- 产品与平台链接分开建模：一款/家族共用货源、原货号、产品事实与候选；A/B/C和同款存量后缀仅关联商品ID及各自发布/验收状态。一次款式溯源服务全部兄弟链接；未核的逐链接换款不能自动标为通过。
- 本地与国际站对应、当前资料唯一入口及“双改”完成门遵守根[商品对应与双改](../AGENTS.md#商品对应与双改负责人2026-10-10明确要求)和[商品SOP](../02_Alibaba运营/00_运营SOP/国际站商品全生命周期SOP.md#本地平台对应及双改完成门2026-10-10)。分类使用台账与生成视图，不因分类调整反复搬动媒体；仅保留有独立证据/调用用途的其他位置，删除重复副本前核内容及引用。
- 新业务先使用已有业务总入口；只有独立对象、独立生命周期或明确复用职责才拆文件。拆分后正文仍只有一个维护位置，入口不再复制正文；不要为精简另建多层说明或整理报告。
- 开始前选定业务或项目目录；不要在根目录建英文临时工程或新的 output/tmp。
- 商品、客户、视频项目保持稳定 ID 和原始证据关联。正式结果与回执写回项目；运行缓存放 99_临时区下可识别的任务目录。
- 通用 AI 视频按在制、已完成、暂停、参考研究、历史待补档案分层。用户未验收的渲染保留在制状态。
- 已有同用途文档必须原地更新，避免“最终版/新版/总控2”；入口不堆日期摘要。保留旧回执须注明历史时间、范围与用途，不能让旧暂停/旧线程分工覆盖当前指令。
- 先判定新内容属于哪一个事实源：原件、当前状态、执行 SOP、Skill 方法、项目记录、长期记忆或历史回执。若现有来源已承载同一结论，更新该处并修引用，不另建摘要。
- 版本号只表示生成顺序。指导文件通过原路径原地修订；素材和回执允许保留版本以追溯，但“现行可用”必须由验收结论和稳定入口指向，不能从最高 `vN` 推断。被撤销的版本退出默认入口，保留其失败证据与受影响记录。
- 项目经验先记在项目记录；只有可解释的机制、明确适用范围和跨项目复现或充分对照证据，才考虑归入共享方法。新增长期记忆及经验晋级遵守确认规则；整理不得把旧观察改写成新事实。
- 移动目录须检查进程、引用、嵌套 Git 与 Junction 目标，更新所有活动入口。跨盘迁移整包后验证文件数、内容哈希，再认为完成。

## 什么删除，什么保留

| 判断 | 处理 |
| --- | --- |
| 完全重复且没有独立调用用途 | 保留唯一可用源，修引用后删除副本 |
| 已被当前规则取代的指导、空占位、已完成迁移脚本 | 直接删除，不创建备份或“旧版”副本 |
| 可重建渲染缓存、日志 | 正式结果存在且无运行引用时删除 |
| 原始数据包、客户沟通、正式发布/测试回执 | 按业务追溯用途保留，不按年龄或体积删除 |
| 旧状态仍有历史证据价值 | 标注日期与范围，不进入默认上下文 |
| 工具规格、实时商品/客户/云实例状态 | 回到当前工具或原始记录核验，记忆仅保存必要入口 |

### 临时区保留期

`99_临时区/` 默认保留期 **30 天**，自目录内最后一次写入起算。超期只进入「待清理候选」，不自动删除；仍须负责人确认，并按[临时区说明](../99_临时区/README.md)的三条清理条件核对（正式回执已保存、无活动引用、可重建）后才删除。被当前经营主线引用的目录可续期，但须写明理由。根层不放散件。

记忆新增与经验晋级仍由用户确认；明确授权的维护按授权直接做，不重复询问已确认事项。整理不刷新事实确认日期，也不创造新的工厂能力或商品供给结论。

## Skills 维护

先查 [Skills清单](../07_知识库与Skills/03_Skills清单.md)。项目技能、个人通用技能和插件有明确来源；保留差异后才能合并，不按同名推断等价。入口只放改变决策的约束与按需路由，长规格放 references。删除入口同步修改依赖、锁文件和清单。

每个 Skill 写清触发动作与不负责的相邻动作；广义任务入口只路由到窄能力，不默认串读多个 Skill。示例、模板和旧市场观察不构成 SKU 事实或永久规则。冲突时先改权威 SOP 或原始记录，再同步修改引用它的 Skill。

Skill 正文中的 `## Required reads` 是维护检查识别的强制读取声明；`## Conditional reads` 或 `## Conditional execution and references` 只在条件成立时读取或执行。普通导航链接不构成调用边。运行器不会自动执行这些标题，实际代理仍须按请求范围判断；修改依赖时用只读检查与任务回归场景复核。

## Git 边界

提交、推送、敏感数据和其他任务改动的权威策略见根 [AGENTS.md](../AGENTS.md#记忆维护与-git)。根仓库跟踪业务文本、SOP、记忆、项目 Skills 和自研脚本；原始/可发布媒体、依赖、第三方工程、浏览器登录态、凭证和独立站嵌套仓库保持本地。历史 Git 对象按正常保留期维护，不强制清空恢复历史。

## 日常检查

产品台账更新后先运行生成工具；`--check`可仅验证总文件、查询页和CSV是否与台账一致，不写文件。工具还核对ID唯一、A/B/C归属、来源引用、候选与正式绑定边界及证据路径。

完整目录回执保存到 `02_Alibaba运营/05_扩品工程/数据/目录对账/当前平台目录/`。运行 `reconcile_product_catalog.py` 预览本轮ID及资产入口差异，确认完整分页后加 `--apply` 更新唯一台账，再生成查询视图。该工具只登记对应、候选分类和待核项，不修改平台、不删除文件，不将标题观察升格为产品事实。

```powershell
python "08_工具链/06_工作区维护/build_product_workspace.py"
python "08_工具链/06_工作区维护/build_product_workspace.py" --check
```

工作区检查会同时验证这些生成结果，并拒绝总控台新出现的日期整理报告。在根目录运行：

```powershell
python "08_工具链/06_工作区维护/check_workspace.py"
```

该检查只读，核对根目录、活动文档与显式代码路径、当前状态入口、版本化治理文件、记忆 ID/来源/替代/索引、项目 Skills 清单/声明的强制依赖，以及链接目录与 Git 边界；可加 `--json` 输出机器可读结果。它不判断语义相似是否真正重复，也不替代逐 SKU、在线业务或视频验收。[任务回归场景](../08_工具链/06_工作区维护/任务回归场景.md)供真实 Agent 行为回放，写出场景本身不算通过。整理或移动后运行一次；无新改动无需反复全量盘点。
