# 工作区维护

本页定义文件归属与维护方式；项目事实和专项执行规则分别由根 AGENTS、原始证据、业务 SOP 管理。

## 单一职责

| 内容 | 唯一维护位置 |
| --- | --- |
| AI 总入口与条件式门禁 | 根 AGENTS.md；专项规则放业务目录 AGENTS/SOP |
| 当前业务证据入口 | 当前状态.md；不抄逐款、逐客户实时数值 |
| SKU 路由与核验队列 | 产品经营主表.md → 原始商品与最新回执 |
| 跨渠道方法与指标 | 跨渠道经营总览.md；不再保留过时“当前状态”表 |
| 全目录导航 | 资产索引.md；只指向有效入口 |
| 长期判断、已确认偏好 | 项目记忆库；正文一处、索引一行、按需读取 |
| 可复用执行方法 | Skill；API/模型参数回到中央规范与当前帮助 |
| 单次工作 | 对应业务目录或视频 PROJECT.md；不自动升格为记忆 |

## 新工作如何落盘

- 开始前选定业务或项目目录；不要在根目录建英文临时工程或新的 output/tmp。
- 商品、客户、视频项目保持稳定 ID 和原始证据关联。正式结果与回执写回项目；运行缓存放 99_临时区下可识别的任务目录。
- 通用 AI 视频按在制、已完成、暂停、参考研究、历史待补档案分层。用户未验收的渲染保留在制状态。
- 已有同用途文档优先更新，避免“最终版/新版/总控2”。保留旧回执须注明历史时间、范围与用途。
- 移动目录须检查进程、引用、嵌套 Git 与 Junction 目标，更新所有活动入口。跨盘迁移整包后验证文件数、内容哈希，再认为完成。

## 什么删除，什么保留

| 判断 | 处理 |
| --- | --- |
| 完全重复且没有独立调用用途 | 保留唯一可用源，修引用后删除副本 |
| 已被当前规则取代的指导、空占位、已完成迁移脚本 | 直接删除，不创建备份或“旧版”副本 |
| 可重建渲染缓存、日志 | 正式结果存在且无运行引用时删除 |
| 原始数据包、客户沟通、正式发布/测试回执 | 按业务追溯用途保留，不按年龄或体积删除 |
| 旧状态仍有历史证据价值 | 标注日期与范围，不进入默认上下文 |
| 工具规格、实时商品/客户/云实例状态 | 回到当前工具或原始记录核验，记忆仅保存必要入口 |

记忆新增与经验晋级仍由用户确认；明确授权的维护按授权直接做，不重复询问已确认事项。整理不刷新事实确认日期，也不创造新的工厂能力或商品供给结论。

## Skills 维护

先查 [Skills清单](../07_知识库与Skills/03_Skills清单.md)。项目技能、个人通用技能和插件有明确来源；保留差异后才能合并，不按同名推断等价。入口只放改变决策的约束与按需路由，长规格放 references。删除入口同步修改依赖、锁文件和清单。

## Git 边界

根仓库跟踪业务文本、SOP、记忆、项目 Skills 和自研脚本。原始/可发布媒体、依赖、第三方工程、浏览器登录态、凭证、独立站嵌套仓库保持本地。推送前确认目标为私有仓库，并检查暂存路径和秘密信息。历史 Git 对象按正常保留期维护，不强制清空恢复历史。

## 日常检查

在根目录运行：

```powershell
python "08_工具链/06_工作区维护/check_workspace.py"
```

该检查只读，核对根目录、活动文档链接、记忆格式/索引、项目 Skills 与 Git 边界；可加 `--json` 输出机器可读结果。它不替代逐 SKU 审核、在线业务验证或视频验收。整理或移动后运行一次；无新改动无需反复全量盘点。
