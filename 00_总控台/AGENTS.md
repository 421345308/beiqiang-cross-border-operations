# 贝强任务路由与协作工作流

本页是所有 Agent 共用的工作流：从本地目标接任务，完成实际交付，把结果写回原业务源。公司事实与授权回根 [AGENTS](../AGENTS.md)，经营目标与跨业务排序只在[当前状态](当前状态.md)维护。

## 开始任务

1. 新会话先读 [当前状态](当前状态.md)，确认这项工作服务哪个目标；用户指定的任务直接优先。随后识别全局协调、单项经营、客户项目或独立创作；只有跨渠道问题才展开 [全渠道增长总控](全渠道增长总控.md)。
2. 从下表只取所需业务入口，随后读适用的下级 AGENTS 和专项 SOP。需要历史依据再搜相应对象ID或章节，旧报告不自动成为现行规则。
3. 明确实际交付物及验收：研究结论、商品修复、网站发布、正式触达、样品或数据回收分别判断。已确认事实直接复用，缺口才问；局部登录/API故障不阻断独立工作。
4. 工具按 [渠道接口与插件](../08_工具链/04_MCP与Workctl/渠道接口与插件.md)选择：已连插件/官方 API 优先，结构化导出次之，浏览器用于登录、授权、尚无接口的操作与页面终验。

## 从目标到下一轮

1. **选一项结果。** 在对应业务入口找当前任务，写清本轮交付及怎样判定完成。没有指定事项时，从当前优先级中选一个可推进的瓶颈；不把整个长期目标展开为一次大工程。
2. **落实主办与范围。** 在原任务条目注明主办 Agent/可定位会话和要写的文件或业务对象。合作方按这个范围研究、实现或复核，具体分工见 [Muse–Codex 协作](../08_工具链/04_MCP与Workctl/Muse-Codex协作.md)。
3. **完成并验证。** 从已有证据和工具直接做出可用成果，运行与改动相称的检查。普通小改由主办验证；只有复杂方案、重要外部变更或有争议的结果，才安排另一视角复核。程序通过、平台生效与经营效果按实际交付分别判断。
4. **回写唯一来源。** 实际结果、证据位置、尚未解决的问题和下一动作写回原条目；新发现的事实及方法写入它们所属的业务档案或SOP。提议标明待验证，已确认决定保留理由；不把讨论稿改名为“定稿”就算采纳。
5. **按结果迭代。** 回看哪一步改善了客户推进、零售经营或作品质量，再选择下一项。无效尝试保留有用证据并调整方法；已完成任务退出活动清单，普通过程由Git和原回执追溯。

## 多对话如何共同工作

以业务对象划分任务；不同对象、不同文件可以并行研究和执行。同一文件或同一平台对象由一个主办写回，其他对话提交发现或差异建议。开始写入前重读该条目和现有改动，已有主办时接独立范围或等其交付；不能凭“自己这轮刚启动”覆盖别人的在制成果。全局优先级由本轮总协调任务维护，业务任务只有遇到跨业务取舍变化才更新它。Git提交与推送串行，精确包含本任务范围。

每个在制项目用原入口的一段文字或一行表格保留以下信息即可，已有等价字段直接复用：

| 目标与本轮交付 | 当前结果或状态 | 主办及写入范围 | 下一动作与完成依据 |
| --- | --- | --- | --- |
| 做成什么、对业务有什么用 | 待开始 / 进行中 / 待依赖 / 已完成，并附实际结果 | Agent/会话定位、文件或对象 | 一个具体动作；交付链接、测试或正式回读 |

只有接手必须知道的信息才入正文，不额外建设全局任务数据库、锁服务、双份看板或每轮交接文件。会话ID帮助定位原始过程，项目文档承担接续。中断时先留下已有产物与下一步；恢复时核现状再继续，局部故障不阻断其他可做部分。

## 文件职责

- [当前状态](当前状态.md)：长期方向、中期成果、近期重点及其唯一业务入口。
- [全渠道增长总控](全渠道增长总控.md)：渠道角色与跨渠道依赖；各业务入口维护当前接入和经营事实。
- [跨渠道经营总览](跨渠道经营总览.md)：经营方法、交接字段、统一指标。
- [产品中心](产品中心/README.md)：共用产品与来源；[资产索引](资产索引.md)：全目录导航。
- [工作区维护](工作区维护.md)：资料归属、目录、Git与运行资料维护。
- [Muse–Codex 协作](../08_工具链/04_MCP与Workctl/Muse-Codex协作.md)：默认分工与会话定位；CLI参数只维护在其链接的调用说明。

## 结束与回写

先更新真实业务源，再修需要变化的入口和优先级。草稿不记为发布，提交不记为送达，可抓取不记为收录，收录不记为AI引用或采购转化。客户原件和授权凭证不进入公开同步。按根规则检查、提交并推送本任务范围，保护其他任务未提交内容。
